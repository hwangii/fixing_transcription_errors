## Findings

### 1. Post-clean Ancestry substitution is not the claimed blank-before-fallback transformation

`post-clean-substitution-not-fallback-counterfactual` · **minor** · correctness · confidence: **likely** (implied, depends on unseen data)

**Where:** `MATCHING/1e_tgtns_divided_files.do:14-18, MATCHING/1e_tgtns_divided_files.do:91-110, MATCHING/1e_tgtns_divided_files.do:121-126, MATCHING/1_divide_and_clean_everyoneV5_women_addedV2.do:168-173, MATCHING/1c_tgt_divided_files.do:105-109`

**What the code does**  
The new builder directly executes `replace f_name = f_ans if sf` and `replace l_name = l_ans if sl` on fields that have already passed through `abeclean`. The claimed counterfactual—blanking `InvalidPred` before fallback—would instead substitute Ancestry at `replace namefrst...`/`replace namelast...` and then run `abeclean` again. These operations are known not to be perfectly idempotent: the existing fallback check documents 436 cases where the upstream fallback output differs from `_ans_cleaned`. The new check only examines existing `name_true_cleaned_exists==0` records, not whether the newly substituted `sf`/`sl` records reproduce the pre-clean fallback path.

**Why it matters**  
If sentinel-bearing records include any non-idempotent cases, the new links will measure direct substitution of `_ans_cleaned`, not solely the effect of treating `InvalidPred` as empty in the production pipeline. Exact ABE matching and candidate uniqueness mean even a small set of different cleaned names can change links for those records and competing candidates.

**How to check**  
On the sentinel rows in each shard, copy `f_ans` and `l_ans`, set `sex=1`, run the same `abeclean ..., sex(sex) initial(...) nickname nonysiis`, and count whether the resulting cleaned fallback field differs from the directly assigned `f_ans` or `l_ans`. Alternatively, rebuild one shard from raw model fields after recoding `InvalidPred` to `""` and compare by `id` with `divided_file1940_tgtns_cleaned`.

**Suggested fix**  
Before the full run, add an assertion that the direct assignment equals the production fallback transformation on every `sf | sl` record. If it fails, either rebuild these rows through the upstream fallback-plus-`abeclean` path or describe the estimand as direct `_ans_cleaned` substitution rather than equivalent blank-before-fallback behavior.
