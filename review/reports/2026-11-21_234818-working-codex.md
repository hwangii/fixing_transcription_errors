## Findings

### 1. The no-usable-output rate treats `InvalidPred` as a valid name

`invalidpred-counted-as-usable` · **MAJOR** · correctness · confidence: **likely** (implied, depends on unseen data)

**Where:** `MATCHING/ditto_diag.do:146-154, MATCHING/ditto_diag.do:188-193, MATCHING/results/ditto_diag_SMOKE.md:56-64, MATCHING/results/ditto_diag_SMOKE.md:101-109`

**What the code does**  
The failure indicators use `!(namefrst_ml!="" & namelast_ml_ditto!="")`, so any nonempty sentinel such as `InvalidPred` is classified as usable. The same script separately finds 565 `namefrst_ml` and 348 resolved-surname sentinel values in the Wyoming smoke data, but does not incorporate them into `fail_pre`, `fail_x`, or `fail_h`.

**Why it matters**  
The asserted 9.619% paper benchmark and the before/after fill rates understate unusable output if any sentinel occurs among target records. Downstream fallback logic based on empty strings can likewise pass the literal sentinel to linkage as though it were a name; the target overlap cannot be measured from the supplied smoke table.

**How to check**  
Immediately after constructing `tgt`, run `gen byte fail_sentinel = tgt & (inlist(strtrim(namefrst_ml),"","InvalidPred") | inlist(strtrim(namelast_ml_ditto),"","InvalidPred"))`, followed by `count if fail_sentinel & !fail_pre` and a state tabulation of that condition.

**Suggested fix**  
Create field-level usability indicators that exclude blanks, whitespace-only values, and `InvalidPred`; use them consistently in all failure, agreement, and fallback categories. Recompute the 49-state rate and update the hard-coded assertion and any paper number it supports.

### 2. Agreement with Ancestry and FamilySearch is labeled as being wrong, fixed, or right

`human-consensus-labeled-ground-truth` · **MAJOR** · claims-vs-code · confidence: **verified** (traced in source)

**Where:** `MATCHING/ditto_diag.do:117-119, MATCHING/ditto_diag.do:160-186, MATCHING/ditto_diag.do:365-399, MATCHING/results/ditto_diag_SMOKE.md:74-99`

**What the code does**  
The code defines `nt` by exact Ancestry–FamilySearch agreement, calls a nonmatching model surname `nt_*_l_w`, and defines `nt_d_fix` and `nt_d_break` solely by movement into or out of equality with `namelast`. It further infers “Inherited” versus “Misclassified” from whether the current Ancestry surname equals `prev_namelast`; the report then labels these predicates as wrong, fixed, right, and causes.

**Why it matters**  
Neither source is ground truth, even when the two agree, and equality with the preceding resolved surname does not establish that the enumerator wrote a ditto mark or that the chain head was misread. Consequently the reported 5.37% “fixed,” 0.38% “broken,” and 91.65%/7.89% cause split are agreement diagnostics, not correctness or causal-error estimates.

**How to check**  
Draw a stratified sample from `nt_dw_inh`, `nt_dw_mis`, `nt_d_fix`, and `nt_d_break`; inspect the census images and independently hand-code the written surname, whether a ditto mark was present, and the intended resolved surname. Tabulate the existing labels against those manual labels.

**Suggested fix**  
Relabel the output as movement into/out of agreement with the two-source consensus and describe `inh`/`mis` as surname-pattern proxies. Use an independently hand-validated image sample before making correctness, fix/break, or causal claims.

### 3. The purported cross-image fill also fills same-image resolver gaps

`cross-image-fill-not-restricted-to-crossings` · **minor** · correctness · confidence: **verified** (traced in source)

**Where:** `MATCHING/ditto_diag.do:88, MATCHING/ditto_diag.do:102-114, MATCHING/ditto_diag.do:248, MATCHING/ditto_diag.do:269-271`

**What the code does**  
Although the comments and output define the model fill as cross-image carry, `replace namelast_x = head_ld if de & head_nd & head_ld!=""` omits `head_cross`. It therefore fills every empty ditto surname below a nonempty non-ditto head, including any same-image gap that the existing resolver unexpectedly left empty.

**Why it matters**  
If such same-image gaps exist outside the Wyoming smoke state, the reported model-fill reduction in no-output records will be attributed to crossing image boundaries even though it combines a different failure mode.

**How to check**  
After line 114, run `count if de & head_nd & head_ld!="" & !head_cross` and `assert dx==de_headcross`. The first count identifies the extra same-image fills directly.

**Suggested fix**  
Add `& head_cross` to the replacement if the estimand is specifically cross-image carry. Otherwise rename the fill and report cross-image and same-image resolver gaps separately.
