### 2. The column labeled all US males silently excludes 2,991 eligible men without a state-file match

`us-column-excludes-extract-only-men` · **MAJOR** · correctness · confidence: **verified** (traced in source)

**Where:** `CODE/make_balance_exhibits.do:78-88, CODE/make_balance_exhibits.do:113-114, CODE/make_balance_exhibits.do:178, replication/README.md:249-252, D:/repos/6638fa0fd89fbec05130caeb/DHTS-2026-10-12.tex:447, D:/repos/6638fa0fd89fbec05130caeb/DHTS-2026-10-12.tex:463`

**What the code does**  
After `merge 1:1 histid` with the IPUMS extract, the code explicitly counts eligible using-only observations with `count if _merge==2 & sex==1 & age>=10 & age<.`, but then executes `keep if _merge==3`. Thus `n_us = r(N)` is not all extract males aged 10 or above; it is only those males also present in a `merged_*1940.dta` state file. The README records a 2,991-record difference, while the paper calls the column “all males aged 10 and above.”

**Why it matters**  
The Table 2 population denominator and its observation count do not represent the population claimed in the caption and note. The descriptive means also describe the state-file-covered subset, so simply changing the printed N would not resolve the universe mismatch.

**How to check**  
In Stata, run the merge through line 80 and execute `count if sex==1 & age>=10 & age<.` followed by `count if _merge==3 & sex==1 & age>=10 & age<.` and `count if _merge==2 & sex==1 & age>=10 & age<.`. Confirm that the last count is 2,991 and that the first equals the latter two counts combined.

**Suggested fix**  
Either retain the extract-only records and document how missing detailed characteristics affect each row denominator, or relabel the column and prose as the state-file-covered male population. Do not describe 55,343,368 as every potentially linkable male in the census.

### 3. The master does not preflight or parameterize the 50 state files newly required by the balance script

`new-state-file-dependencies-bypass-preflight` · **MAJOR** · replication · confidence: **verified** (traced in source)

**Where:** `CODE/make_balance_exhibits.do:33-35, CODE/make_balance_exhibits.do:57-68, CODE/make_balance_exhibits.do:90, replication/run_machineA.do:30-49, replication/README.md:81-92`

**What the code does**  
The revised balance script discovers `merged_*1940.dta` under the literal `F:/fixing_transcription_errors/DATA/INTERMEDIATE/` and invokes supporting code through literal `D:\repos\fixing_transcription_errors\CODE\`. Meanwhile, `run_machineA.do` removed the old F: `temp.dta` from `local inputs` but added none of the state files, despite claiming to preflight every frozen input. The README's frozen-input inventory still lists the retired F: `temp.dta`, not the 50 replacement files.

**Why it matters**  
A full run can pass preflight, spend hours rebuilding the analysis file, and then fail or silently use whatever files happen to match the directory wildcard. An external replicator cannot redirect these dependencies through `config.do`, and the archive does not identify the exact required file set.

**How to check**  
Temporarily point `REP_F` at a directory lacking one state file and run `replication/run_machineA.do`; its preflight will still report success. Separately run Stata's `local files : dir ... files "merged_*1940.dta"` and display the word count to show that the dependency set comes from current directory contents rather than the master manifest.

**Suggested fix**  
Define the state-data and paper paths in `replication/config.do`, enumerate the expected jurisdictions explicitly, add every state file to the preflight manifest, assert the expected file count/jurisdictions, and update the README inventory. Use `$REP_REPO/CODE/create_socio_demographic_vars.do` rather than a literal repository path.
