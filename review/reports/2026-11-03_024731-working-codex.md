### 1. The new producing script cannot verify the county-correlates claim because the registry still marks it as having no code

`county-correlates-remains-unchecked` · **MAJOR** · claims-vs-code · confidence: **verified** (traced in source)

**What the code does**  
The new script computes county-level means, splits counties using ``v' > `med'` versus ``v' <= `med'`, and exports `countyIncongAbove*` and `countyIncongBelow*`. But the corresponding registry entry still says `status = "nocode"`, `values = [""]`, and `script = "none for all states"`; `check_claims.py` then unconditionally assigns every `nocode` claim the result `UNCHECKED`.

**Why it matters**  
The draft claims that incongruence is notably higher in all three above-median county groups, but neither the direction nor magnitude is checked against the newly exported results. The committed report confirms that the claim remains UNCHECKED and does not read `compute_county_correlates.tex`, so adding the script to the runner has not established the paper claim.

**How to check**  
Run `rg -n "county-correlates|compute_county_correlates" replication/claims.toml replication/claims_report.md`, then run the machine-A pipeline and claim checker. The county claim will remain UNCHECKED regardless of the generated result file while its status is `nocode`.

**Suggested fix**  
Change the registry entry to `status = "scripted"` with `script = "CODE/compute_county_correlates.do"`, and add an assertion requiring each exported above-median rate to exceed its corresponding at-or-below rate. Run machine A and regenerate `claims_report.md`, committing the generated result file if results are part of the replication archive.

### 2. Working-tree reviews still exit without reviewing when all changes are untracked

`untracked-only-review-exits-empty` · **minor** · correctness · confidence: **verified** (traced in source)

**Where:** `review/Run-Review.ps1:173, review/Run-Review.ps1:191-205`

**What the code does**  
The prompt now tells the reviewer to inspect `git status --short` for `??` files, but the preflight still sets `$diffStat` only from `git ... diff HEAD --stat`. Git diff does not include untracked files, so an untracked-only tree makes `$diffStat` blank and triggers `exit 0` with “No uncommitted changes.”

**Why it matters**  
A newly created analysis or replication file can be omitted from review entirely—the exact failure the prompt change is intended to prevent. This can allow number-changing code to reach submission without an independent review.

**How to check**  
In a throwaway Git repository with a clean commit, create one untracked file and compare `git diff HEAD --stat` with `git status --short`; the former is empty while the latter shows `??`. Running this review driver with `-Target working` will exit at line 204.

**Suggested fix**  
Include `git ls-files --others --exclude-standard` or parsed `git status --porcelain` in the emptiness test, and exit only when both the tracked diff and untracked-file list are empty.
