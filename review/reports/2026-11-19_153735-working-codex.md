## Findings

### 1. The input dataset is saved before `target` is generated, so the new script stops at its first `use`

`target-saved-after-temp-output` · **MAJOR** · correctness · confidence: **verified** (traced in source)

**Where:** `MATCHING/linked_groups_socio.do:30, CODE/create_figures_SSHA2025.do:119, CODE/create_figures_SSHA2025.do:138`

**What the code does**  
The new script executes `use linked_before linked_after age target ... using temp_tgt.dta`. Its producer executes `save ... temp`sfx'.dta` at line 119 and only later executes `gen target=!(namefrst==fs_namefrst & namelast==fs_namelast)` at line 138. Thus `temp_tgt.dta` does not contain the variable needed for the intended target-share calculation at lines 65-66.

**Why it matters**  
Stata will stop with `variable target not found`, before any groups or shares are calculated, and `MATCHING/results/linked_groups_socio.md` will not be written.

**How to check**  
Run `describe target using "$REP_SNU/enum_date/DATA/INTERMEDIATE/temp_tgt.dta"` in Stata, or run the command documented at MATCHING/linked_groups_socio.do:21 and observe the failure at line 30.

**Suggested fix**  
Either generate `target` before saving `temp_tgt.dta`, or load the four Ancestry/FamilySearch name fields in `linked_groups_socio.do` and recreate `target` there with the same definition. Then rerun the existing N and linkage-rate gates.

### 2. The documented standalone run is checkout-specific and the new analysis is absent from the replication master

`new-analysis-has-no-portable-entrypoint` · **MAJOR** · replication · confidence: **verified** (traced in source)

**Where:** `MATCHING/linked_groups_socio.do:17-26, replication/Run-Stata.ps1:35-37, replication/run_machineA.do:96-99`

**What the code does**  
The documented command invokes `Run-Stata.ps1`, whose wrapper only executes the requested do-file. With `$REP_REPO` unset, the do-file then loads `D:/repos/fixing_transcription_errors/replication/config.do`; it also assumes that a prior manual `_figs_tgt_run.do` invocation has created `temp_tgt.dta`. The replication master's script list does not build the target-only input or run this new analysis.

**Why it matters**  
A clean clone outside the author's exact checkout cannot reproduce the new Markdown table from the documented command, and the main replication run silently omits it. This is a broken clean-run path even after the correctness defect is fixed.

**How to check**  
Clear `$REP_REPO` and invoke the documented command from a checkout not located at `D:/repos/fixing_transcription_errors`; it will fail loading the hardcoded config. Also run `rg -n "linked_groups_socio|_figs_tgt_run" replication/run_machineA.do` and confirm neither prerequisite nor analysis is called.

**Suggested fix**  
Provide an orchestrator that loads configuration relative to the resolved repository root, runs `_figs_tgt_run.do`, and then runs `linked_groups_socio.do`; add that sequence to the replication master if this output is part of the submission archive.
