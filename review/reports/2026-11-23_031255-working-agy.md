### 1. Target records with one "InvalidPred" field and one empty model field keep name_true_cleaned_exists==1 and inflate ntgtml

`one-sentinel-one-empty-exists-flag` · **minor** · claims-vs-code · confidence: **verified** (traced in source)

**Where:** `MATCHING/1d_for_mlp_tgtns.do:7-8, MATCHING/1d_for_mlp_tgtns.do:22, MATCHING/1d_for_mlp_tgtns.do:138, MATCHING/1d_for_mlp_tgtns.do:144-145, MATCHING/1d_for_mlp_tgtns.do:170`

**What the code does**  
Line 138 sets `replace name_true_cleaned_exists = 0 if sf & sl`, lines 144-145 count `tgt & name_true_cleaned_exists==1` into `ntgtml`, line 170 reports "`ntgtml' with model names", and line 22 states `name_true_cleaned_exists  1 only for target records with model names`. In MATCHING/1_divide_and_clean_everyoneV5_women_addedV2.do:119,165-170, however, a record entered temptemptemp1.dta with `name_true_cleaned_exists = 1` whenever at least one of `namefrst_ml` or `namelast_ml_ditto` was non-empty, and any empty field was immediately replaced by Ancestry's cleaned name. On target records where one model field was "InvalidPred" and the other was empty "" (15,665 target records across both sexes per MATCHING/results/ditto_diag.md:52-56 and MATCHING/1e_tgtns_divided_files.do:29-33), replacing the sentinel field with Ancestry's fallback leaves no model name in either field, yet `name_true_cleaned_exists` remains 1.

**Why it matters**  
In `for_mlp1940_tgtns.dta`, ~15,665 target records carrying only Ancestry fallback names remain flagged `name_true_cleaned_exists == 1`, and the summary log at line 170 overstates the number of target records with model names (`ntgtml`) by that amount. Unlike MATCHING/1e_tgtns_divided_files.do:29-33, this script exports `name_true_cleaned_exists` in the IPUMS MLP input file without noting the discrepancy.

**How to check**  
In Stata after running 1d_for_mlp_tgtns.do, compare the printed `ntgtml` count against 1d_for_mlp_tgt.log's 34,932,927 minus `nboth`: it drops only two-sentinel rows (`sf & sl`) and still counts the ~15,665 target records where one raw model field in merged_data.dta was "InvalidPred" and the other was "".

**Suggested fix**  
Either document in the header and final display of MATCHING/1d_for_mlp_tgtns.do (as MATCHING/1e_tgtns_divided_files.do:29-33 does) that ~15,665 target records with one sentinel field and one empty model field keep `name_true_cleaned_exists == 1` even though both name fields are Ancestry fallbacks after the fix, or merge a usable-model-output flag from the raw model files so `name_true_cleaned_exists` is set to 0 whenever neither model field is usable.

### 2. Re-running abeclean on already-cleaned Ancestry first names wipes mi_true_cleaned on sentinel-first-name target records

`fallback-double-abeclean-strips-ancestry-mi` · **minor** · correctness · confidence: **verified** (traced in source)

**Where:** `MATCHING/1d_for_mlp_tgtns.do:98-100, MATCHING/1d_for_mlp_tgtns.do:121-136`

**What the code does**  
For non-target records (`!tgt`), lines 98-100 copy Ancestry's cleaned names and middle initial directly from `divided_file1940_ans_cleaned_women_added` (`replace mi_true_cleaned = mi if !tgt`). For target records with a sentinel first name (`sf == 1`), lines 121-136 replicate `1_divide_and_clean_everyoneV5_women_addedV2.do:169-173`'s fallback by passing `f_name` and `l_name` from `divided_file1940_ans_cleaned_women_added` through `abeclean f_fb l_fb, sex(sex) initial(mi_rc) nickname nonysiis` a second time and setting `replace mi_true_cleaned = mi_rc if sf`. Because `f_name` in `_ans_cleaned_women_added` already had its middle initial stripped into `mi` during the first `abeclean` pass (`0_create_file_for_matching_intgenV4_women_added.do:87`), the second `abeclean` pass yields `mi_rc == ""` for >99% of sentinel first names (all except two-initial first names such as "j w" where `abeclean.ado:233-234` left a space in `f_name`).

**Why it matters**  
Target records that fall back to Ancestry's first name because the model output was "InvalidPred" (or empty) lose Ancestry's middle initial `mi` in `mi_true_cleaned`, whereas non-target records falling back to Ancestry's first name retain `mi_true_cleaned = mi`. Any MLP linking step or middle-initial validation that uses `mi_true_cleaned` treats these fallback target records as having no 1940 middle initial.

**How to check**  
Inside the loop in MATCHING/1d_for_mlp_tgtns.do after line 135 (or comparing `for_mlp1940_tgtns.dta` against `mi`), run `count if sf & mi != "" & mi_true_cleaned == ""` to count sentinel-first-name target records whose Ancestry middle initial `mi` is blanked out by the second `abeclean` pass.

**Suggested fix**  
Verify whether IPUMS MLP linking and downstream HLINK/MLP evaluation use `mi_true_cleaned`; if a missing/sentinel model first name is intended to fall back to Ancestry's transcription on target records the same way non-target records do at lines 98-100, assign `replace namefrst_true_cleaned = f_name if sf` and `replace mi_true_cleaned = mi if sf`, or report fixed Ancestry-MI validation alongside own-MI in downstream MLP tables.

### 3. abeclean is invoked mid-loop without adding the repo's abeclean.ado directory to adopath or checking which abeclean up front

`untracked-abeclean-path-and-preflight` · **minor** · replication · confidence: **verified** (traced in source)

**Where:** `MATCHING/1d_for_mlp_tgtns.do:38, MATCHING/1d_for_mlp_tgtns.do:123`

**What the code does**  
Line 38 loads `replication/config.do`, which adds only `$REP_REPO/replication/stata` to `adopath` (`replication/config.do:44`), and line 123 calls `abeclean f_fb l_fb, sex(sex) initial(mi_rc) nickname nonysiis` inside the 144-file loop. In this repository, `abeclean.ado` resides in `LINKAGE/code/01_abe_jw/reference/abeclean.ado` (and `comparison/abeclean.ado`), not in `replication/stata/`. Unlike `MATCHING/_tgtns_run.do:18`, `MATCHING/1d_for_mlp_tgtns.do` does not run `which abeclean` before starting the loop.

**Why it matters**  
On Machine A, `abeclean` resolves only because a copy was placed inside Stata's system folder `C:\Program Files (x86)\Stata15\ado\base\a\abeclean.ado` (`MATCHING/_tgtns_run.log:171-172`). On a clean replicator machine, `1d_for_mlp_tgtns.do` will fail inside the loop at line 123 with `r(199)`, and logs on Machine A will not record which `abeclean.ado` binary was used.

**How to check**  
Inspect `replication/config.do:44` and `replication/stata/` (which contains only `repnum.ado`), or run `MATCHING/1d_for_mlp_tgtns.do` on a Stata installation where `abeclean.ado` has not been manually copied into Stata's system `ado/base/a/` directory.

**Suggested fix**  
Place `abeclean.ado` in `replication/stata/` (or add `adopath ++ "$REP_REPO/LINKAGE/code/01_abe_jw/reference"`), add `which abeclean` before the `foreach f of local fT` loop at line 65 (as `MATCHING/_tgtns_run.do:18` does), and add a verification script or runner entry analogous to `MATCHING/compare_for_mlp_tgt.do`.
