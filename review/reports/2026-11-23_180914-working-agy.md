## Findings

### 1. merge 1:1 histid using tgt_flag1940.dta aborts with variable histid not found (r(111)) because tgt_flag1940.dta keys on id

`flags-merge-key-mismatch-crashes` · **BLOCKER** · correctness · confidence: **verified** (traced in source)

**Where:** `MATCHING/check_mlp_abe_fname_diff.do:38, MATCHING/1c_tgt_divided_files.do:64-65, MATCHING/compare_for_mlp_tgt.do:51-55`

**What the code does**  
Line 34 loads `histid` from `for_mlp1940_tgtns.dta`, line 35 merges `abe` on `histid`, and line 38 runs `merge 1:1 histid using "`flags'", keep(1 3) keepusing(tgt)`. However, `MATCHING/1c_tgt_divided_files.do:64-65` saves `tgt_flag1940.dta` after `rename histid id`, so `tgt_flag1940.dta` contains `id` and `tgt`, not `histid`. Every other script that merges `tgt_flag1940.dta` either merges on `id` (`1c_tgt_divided_files.do:100`, `1d_for_mlp_tgt.do:79`, `1d_for_mlp_tgtns.do:101`, `1e_tgtns_divided_files.do:89`) or renames `histid` to `id` before the merge and back to `histid` afterward (`compare_for_mlp_tgt.do:51-55`).

**Why it matters**  
Stata aborts at line 38 with `variable histid not found` (`r(111)`) before executing the target/model-flag tabulation, the `abeclean` reproduction test, or the discrepancy examples.

**How to check**  
Run `describe using "$REP_F/enum_date/DATA/INTERMEDIATE/tgt_flag1940.dta"` in Stata (or inspect `MATCHING/1c_tgt_divided_files.do:64-65` and `MATCHING/compare_for_mlp_tgt.do:51-55`) to confirm the identifier variable in `tgt_flag1940.dta` is `id`, not `histid`.

**Suggested fix**  
Rename `histid` to `id` before merging `tgt_flag1940.dta` and back to `histid` afterward (as in `MATCHING/compare_for_mlp_tgt.do:51-55`), and drop the unused `tgt` variable: `rename histid id` / `merge 1:1 id using "`flags'", keep(1 3) keepusing(tgt)` / `rename id histid` / `gen byte tgt1 = _merge==3` / `drop _merge tgt`.

### 2. Script does not test abeclean on raw model names (despite the header claim) or check loaded a_ex and a_mi fields

`raw-model-name-and-companion-fields-untested` · **minor** · claims-vs-code · confidence: **verified** (traced in source)

**Where:** `MATCHING/check_mlp_abe_fname_diff.do:5-6, MATCHING/check_mlp_abe_fname_diff.do:22-23, MATCHING/check_mlp_abe_fname_diff.do:34, MATCHING/check_mlp_abe_fname_diff.do:48-63`

**What the code does**  
The header comment (`lines 5-6`) states `Test: run abeclean on the MLP name (and on the raw model name) and see whether it reproduces the ABE name.` Lines 49-57 only run `abeclean` on `f_test = namefrst_true_cleaned` (the stored MLP name in `for_mlp1940_tgtns.dta`) and never load raw model names (`namefrst_ml`) or test `abeclean` on `a_f`. In addition, lines 22-23 and 34 load `a_l`, `a_mi`, `a_ex`, and `mi_true_cleaned`, and line 51 generates `mi_test`, but none of those variables is ever checked or tabulated, and `contract namefrst_true_cleaned a_f` at line 61 drops `f_test_cleaned` and `reproduces` before listing the top 40 pairs with an unguarded `in 1/40`.

**Why it matters**  
`MATCHING/check_mlp_abe_same_input.log:448-451` reported 487 middle-initial differences (`d_mi`) and 5 model-name-flag differences (`d_ex`) alongside the 61,959 first-name differences. Because `abeclean` splits multi-token first names into first name and middle initial (`LINKAGE/code/01_abe_jw/reference/abeclean.ado:232-241`), ignoring `mi_test` vs. `a_mi` and `a_ex` vs. `name_true_cleaned_exists` (and dropping `f_test_cleaned` from the `contract` table) omits direct evidence on whether multi-token splitting or flag mismatches account for any of the 61,959 cases.

**How to check**  
Inspect `MATCHING/check_mlp_abe_fname_diff.do:22-64` and verify that raw model names (`namefrst_ml`) are never loaded and that `a_ex`, `a_mi`, `a_l`, `mi_true_cleaned`, and `mi_test` are never referenced after being loaded or generated.

**Suggested fix**  
Either update the header comment at line 6 to remove `(and on the raw model name)` or merge the raw model transcription; tabulate `tab name_true_cleaned_exists a_ex, missing` and check `count if mi_test == a_mi` (especially on the 487 records where `mi_true_cleaned != a_mi`); include `f_test_cleaned reproduces` in `contract namefrst_true_cleaned f_test_cleaned a_f reproduces` at line 61; and guard `list` ranges at lines 60 and 63 with `in 1/`=min(40,_N)''`.
