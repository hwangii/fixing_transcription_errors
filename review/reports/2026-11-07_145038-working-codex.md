**What the code does**

The matching master exits after constructing one requested FamilySearch configuration, while `run_machineA.do` invokes only its fixed CODE and diagnostic script lists; its preflight includes the Ancestry and ML links but none of the three `link1930_1940_fs*.dta` inputs.

**Why it matters**

**How to check**

**Suggested fix**  
Add a documented top-level FamilySearch workflow that builds or preflights all three FamilySearch link variants, invokes `MATCHING/fs_avg_performance.do`, and registers its TeX output. Include the divided-file directories and link datasets in preflight checks.

### 2. FamilySearch exposure is reported only among records that successfully link

`familysearch-exposure-conditioned-on-linkage` · **minor** · identification · confidence: **verified** (traced in source)

**Where:** `MATCHING/fs_avg_performance.do:81-96, MATCHING/fs_avg_performance.do:119-122, MATCHING/fs_avg_performance.do:173-184, MATCHING/1b_fs_divided_files.do:83-94`

**What the code does**  
The divided files define FamilySearch use before matching through `fs_frst_used` and `fs_last_used`. The scorer instead generates `fs<year>_<combo>` only `if linked_<combo>==1`, and the reported means therefore measure the share of successful links using a FamilySearch field, not FamilySearch availability or substitution in the underlying candidate population.

**Why it matters**  
The FamilySearch specifications are hybrid policies that fall back field by field to Ancestry. If FamilySearch availability is selective, differences in linkage rates across the three specifications combine transcription performance with differing exposure; conditional-on-linkage usage cannot distinguish those mechanisms.

**How to check**  
Append each year's `divided_file<year>_fs_cleaned/norace*.dta` files and tabulate `fs_frst_used | fs_last_used` over the eligible divided-file population. Compare those rates with the conditional linked-record rates produced at MATCHING/fs_avg_performance.do:119-122.

**Suggested fix**  
Report pre-link FamilySearch substitution coverage for each eligible census-year population, alongside the existing conditional-on-linkage rows. Keep the columns explicitly labeled as FamilySearch with field-level Ancestry fallback.
