## Findings

### 1. The FamilySearch target-only driver calls the stage-2 master with the core matcher’s arguments

`fs-target-stage2-wrong-entrypoint` · **MAJOR** · correctness · confidence: **verified** (traced in source)

**Where:** `MATCHING/_fs_tgt_run.do:58, MATCHING/2_ABE_matchingV3_master_christian_torben.do:1-15, MATCHING/2_ABE_matchingV3_christian_torben.do:17-25`

**What the code does**  
Line 58 executes `2_ABE_matchingV3_master_christian_torben.do 1930 1940 "_fs_cleaned" 1 "_tgt_cleaned"`. The master interprets those positions as year list, interval, location, FamilySearch years, and FamilySearch type, respectively; thus it receives interval 1940 and location `_fs_cleaned`. The five supplied arguments instead match the signature of the non-master `2_ABE_matchingV3_christian_torben.do`, where they mean year 1, year 2, type A, location, and type B.

**Why it matters**  
The driver fails before creating `r_fs_cleaned_tgt_cleaned1930_1940`, so the intended target-only mixed link file and its slide result cannot be produced.

**How to check**  
Run `powershell -File replication/Run-Stata.ps1 MATCHING/_fs_tgt_run.do`; the log should stop at the stage-2 call and never print `FS-TGT-DONE`. The mismatch is also visible with `rg -n '^local (yr_list|interval|location|fs_years|fstype|ml_years)|2_ABE_matchingV3' MATCHING/_fs_tgt_run.do MATCHING/2_ABE_matchingV3_master_christian_torben.do MATCHING/2_ABE_matchingV3_christian_torben.do`.

**Suggested fix**  
At line 58, call `2_ABE_matchingV3_christian_torben.do` rather than its master, retaining the five existing arguments. Alternatively, extend the master with an explicit `mltype` argument and invoke it using its actual year-list/interval/location signature.

### 2. The slide-table generator still reads the all-record ML link, leaving the new target-only link unused

`target-only-fs-link-unused` · **MAJOR** · replication · confidence: **verified** (traced in source)

**Where:** `MATCHING/_fs_tgt_run.do:6-12, MATCHING/fs_avg_performance.do:37-44, MATCHING/fs_avg_performance.do:166-175`

**What the code does**  
The new driver is intended to write `link1930_1940_fs1930_mltgt1940_cleaned_noraceblock0.dta`, but slide mode defines `f_fs30ml` as `link1930_1940_fs1930_ml1940_cleaned_noraceblock0.dta` and adds only that old `fs30ml` combination. No table-generating code references the new `mltgt` stem.

**Why it matters**  
Any slide table regenerated through the documented `do MATCHING/fs_avg_performance.do slides` path continues to report the all-record ML-1940 linkage and agreement rates, not the intended target-only rates.

**How to check**  
Run `rg -n 'fs1930_ml(tgt)?1940|f_fs30ml' MATCHING/_fs_tgt_run.do MATCHING/fs_avg_performance.do`; the target-only filename appears only in the driver, while the slide generator points to the old file.

**Suggested fix**  
In slide mode, point the mixed column to the `fs1930_mltgt1940` file, or add it as a separately named combination if both versions are required. Label it explicitly as target-only and regenerate `MATCHING/results/fs_avg_performance_slides.tex`.
