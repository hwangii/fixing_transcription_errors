## Findings

### 1. The middle-initial validator changes for identical linked pairs, so its increase does not identify improved match quality

`changing-validator-confounds-match-quality-gain` · **MAJOR** · claims-vs-code · confidence: **verified** (traced in source)

**Where:** `replication/diagnostics/validation_by_link_status.do:35-52, replication/results/validation_by_link_status.tex:23-26, CODE/create_figures_SSHA2025.do:70-86, D:/repos/6638fa0fd89fbec05130caeb/DHTS-2026-10-12.tex:96-99, D:/repos/6638fa0fd89fbec05130caeb/DHTS-2026-10-12.tex:547-549`

**What the code does**  
The upstream analysis independently imports `mi1930` and `mi1940` from each old- and new-name link file and constructs `validated_before=mi1930==mi1940` and `validated_after=mi1930==mi1940`. The diagnostic defines kept links as the identical source and target IDs, yet their target-sample validation rate changes from 63.4% to 79.2%. It also records 165,580 kept links whose validation value changes. Thus the purported validator is itself altered between the before and after measurements even when link correctness cannot have changed.

**Why it matters**  
The paper calls the 65% to 84% increase a 28% improvement in “match quality” and uses it to infer recovery of true rather than spurious matches. A measure that rises by 15.8 percentage points for unchanged pairs conflates changes in middle-initial transcription or availability with changes in link correctness, so it cannot support that interpretation.

**How to check**  
For `status==1`, merge a single independently sourced middle initial for each fixed 1930 and 1940 ID, then tabulate agreement once rather than using the initials carried by the two link files. Also run `tab validated_before validated_after if status==1 & congruent==0, missing` to display the transition matrix behind the 63.4% to 79.2% change.

**Suggested fix**  
Construct validation from middle initials held fixed across specifications and not produced by the old/new name transcription being evaluated. If no independent fixed measure exists, describe the current rates as transcription-dependent middle-initial consistency rather than match quality and remove the inference that their increase demonstrates true-link recovery.

### 2. The generated result file defines nKeptAll twice and causes every automated claim check to abort

`duplicate-result-key-breaks-claim-checker` · **MAJOR** · replication · confidence: **verified** (traced in source)

**Where:** `replication/diagnostics/validation_by_link_status.do:48, replication/diagnostics/validation_by_link_status.do:59-69, replication/results/validation_by_link_status.tex:4, replication/results/validation_by_link_status.tex:12, replication/check_claims.py:38-50`

**What the code does**  
The script first writes `repnum nKeptAll = `nk'`. During the `All` loop, the `Kept` specification writes `repnum n`2'`smp'`, which expands to `nKeptAll` again. `check_claims.py` deliberately exits whenever `key in vals`, so merely loading `replication/results/*.tex` now terminates with a duplicate-key error before checking any paper claims.

**Why it matters**  
Both machine replication drivers invoke the claim checker. Consequently, the commit makes the package’s main automated claims-versus-results validation fail even if all substantive outputs reproduce.

**How to check**  
Run `python -c "import importlib.util,pathlib; p=pathlib.Path('replication/check_claims.py'); s=importlib.util.spec_from_file_location('cc',p); m=importlib.util.module_from_spec(s); s.loader.exec_module(m); m.load_results(pathlib.Path('replication/results'))"`. It exits with `duplicate result key \nKeptAll in validation_by_link_status.tex and validation_by_link_status.tex`.

**Suggested fix**  
Remove the first redundant `nKeptAll` output or give the diagnostic total a distinct key, regenerate the TeX file, and rerun the full claim checker.

### 3. The 86.1% added-link statistic applies only to links with observed initials, but the committed output reports only the much larger total-link count

`added-link-rate-omits-selected-validation-denominator` · **MAJOR** · identification · confidence: **verified** (traced in source)

**Where:** `replication/diagnostics/validation_by_link_status.do:61-69, replication/diagnostics/validation_by_link_status.log:344-346, replication/results/validation_by_link_status.tex:31-32, D:/repos/6638fa0fd89fbec05130caeb/DHTS-2026-10-12.tex:547-549`

**What the code does**  
For added links the code runs `summarize validated_after`, whose `r(mean)` excludes missing validation values, but saves `nlinks` from `count if status==3`, including links without initials. It displays the actual `r(N)` only in the ignored runtime log and never writes it to the committed result. That run shows 1,953,052 target-group added links but only 396,760 with initials, so the reported 86.1% describes about 20.3% of added links.

**Why it matters**  
Middle-initial availability is selective and may correlate with name structure, transcription difficulty, or link correctness. The 86.1% rate therefore does not establish that the full set of nearly two million added links is high quality, while the paired committed macros can easily be read as a rate over all 1,953,052 links.

**How to check**  
Run `tab status if congruent==0` and, within each status, tabulate `!missing(validated_before)` and `!missing(validated_after)`. Compare validation rates and observable-initial shares for added, dropped, kept, and switched links, including relevant demographic and name-difficulty covariates.

**Suggested fix**  
Persist the nonmissing `r(N)` and initial-availability percentage for every status group, report that the added-link rate covers only 396,760 of 1,953,052 links, and examine whether availability differs systematically. Limit any quality claim to the observable-initial subset unless an additional validation source covers the remainder.
