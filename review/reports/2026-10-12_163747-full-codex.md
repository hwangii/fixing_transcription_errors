### 1. The named headline-results generator excludes four jurisdictions while the paper claims all tables cover 49

`headline-results-drop-four-jurisdictions` · **MAJOR** · claims-vs-code · confidence: **verified** (traced in source)

**Where:** `CODE/create_figures_SSHA2025.do:89-109, D:/repos/6638fa0fd89fbec05130caeb/DHTS-2024-11-18.tex:378-385, D:/repos/6638fa0fd89fbec05130caeb/DHTS-2024-11-18.tex:500-515`

**What the code does**  
After loading the purported all-state analysis file, the script executes `drop if state_folder_name=="district-of-columbia"|state_folder_name=="minnesota"|state_folder_name=="mississippi"|state_folder_name=="missouri"` and only then computes the before/after means with `sum linked_before` and `sum linked_after`. It also merely displays the ratios; it contains no command that writes `avg_performance_allstates.tex`, despite the paper’s statement that this do-file generated that table.

**Why it matters**  
The paper says every table covers the same 48 contiguous states plus DC, but its cited generator computes the 119%, 28%, 8%, and 1% changes after removing DC and three states. The current source therefore cannot establish that the headline results apply to the stated population, and the published table cannot be regenerated from its named producer.

**How to check**  
Run `tab state_folder_name` immediately before and after line 91, then recompute lines 95-125 both with and without the drop. Also run `rg -n "avg_performance_allstates|file write|esttab|texsave" CODE/create_figures_SSHA2025.do CODE` to confirm that no repository code writes the claimed table.

**Suggested fix**  
Remove the four-jurisdiction exclusion or explicitly disclose and justify the narrower universe. Add code that writes the table directly from the calculated scalars, records jurisdiction coverage, and asserts the expected state count before producing results.

### 2. The headline table silently uses smaller denominators than the analysis sample described in the text

`headline-table-denominators-do-not-match-analysis-sample` · **MAJOR** · claims-vs-code · confidence: **verified** (traced in source)

**What the code does**

**Why it matters**  
The 119% and 8% headline rates are not calculated over the sample the paper says they describe: 29,344 all-sample records and 11,237 target records disappear. If the omitted records have missing covariates or unavailable links, the reported rates are conditional on additional availability rather than applying to every complete-name record.

**How to check**

**Suggested fix**  
Define one analysis-sample flag before any merges, report a complete attrition table, and use that same flag for the descriptive and headline tables. If linkage inputs require a narrower sample, revise the prose and table note to give its exact eligibility rule and denominator.

### 4. Higher model agreement with FamilySearch is incorrectly interpreted as evidence that FamilySearch is more reliable

`familysearch-reliability-inferred-from-model-agreement` · **MAJOR** · claims-vs-code · confidence: **verified** (traced in source)

**Where:** `CODE/compute_model_agreement_on_discordant.do:116-130, CODE/compute_model_agreement_on_discordant.do:161-174, D:/repos/6638fa0fd89fbec05130caeb/DHTS-2024-11-18.tex:293-297`

**What the code does**  
The human-complete calculations count exact string equality: `fs_namefrst==namefrst_ml & fs_namelast==namelast_ml_ditto` versus the analogous Ancestry expression. They contain no image review, adjudication, or external truth field. The resulting 14.3% and 51.8% are resemblance rates between sources, not source-specific correctness rates.

**Why it matters**  
The draft concludes that the 52% versus 14% split suggests FamilySearch is more reliable. The same pattern could arise from source-correlated preprocessing, model bias, or shared conventions; without ground truth it says only that the model resembles FamilySearch more often. This is exactly the agreement-versus-accuracy distinction on which the paper’s central claim depends.

**How to check**  
Draw a random sample from the four human-complete categories at lines 119-130, blind the source labels, and adjudicate each name directly from the census image. Tabulate source correctness separately from source agreement.

**Suggested fix**  
Replace the reliability inference with the descriptive statement that the model agrees more often with FamilySearch. Make any comparative reliability claim only from a blinded, hand-validated sample with a stated protocol and confidence intervals.
