### 1. Subtracting target from all-record tables compares global Old vs. New runs rather than identifying the effect of target-only replacement

`old-vs-new-does-not-identify-target-only-effect` · **MAJOR** · identification · confidence: **verified** (traced in source)

**Where:** `MATCHING/nontarget_from_tables.py:3-6, MATCHING/nontarget_from_tables.py:53-63, MATCHING/2_ABE_matchingV3_christian_torben.do:158-167, review/briefs/2026-11-17-nontarget-from-tables.md:3`

**What the code does**  
MATCHING/nontarget_from_tables.py:53-63 subtracts the restricted (target) Panel A counts from the full (all-records) Panel A counts for the existing global Old (all-Ancestry) and global New (all-model) linkage tables, and compares Old to New on the 36,620,316 non-target records. Neither input table was generated under the target-only policy. In all three linking methods (e.g., MATCHING/2_ABE_matchingV3_christian_torben.do:158-167, which calls abematch with unique_m(2) unique_f(2) and keeps unique_file2 == 1 & unique_match2 == 1), matching and uniqueness are determined globally across all records in each birthplace/age cell.

**Why it matters**  
Changing 1940 names on the 14.4M target records alters candidate sets and uniqueness for the 36.6M non-target records via equilibrium linkage spillovers. Consequently, the change from Old to New on non-target records in the existing tables conflates (a) the direct effect of using model names on non-target records and (b) candidate-competition spillovers from changing target record names. It cannot answer the brief's stated question of whether replacing names on all records hurts relative to replacing names only on target records.

**How to check**  
Once MATCHING/_tgt_only_run.do completes, score link1930_1940_mltgt1940_cleaned_noraceblock0.dta and link1930_1940_ml1940_cleaned_noraceblock0.dta directly on the 36,620,316 non-target records (target == 0 in linkage_sample1940.dta) and compare their match rates and Verified/Unverifiable/Contradicted counts against the All-minus-Target Old vs. New difference reported by MATCHING/nontarget_from_tables.py.

**Suggested fix**  
Label the output of MATCHING/nontarget_from_tables.py strictly as a descriptive decomposition of how non-target records fared between the global Old and global New linkage runs. To evaluate whether replacing names on all records hurts relative to replacing names on target records only, score link1930_1940_mltgt1940_cleaned_noraceblock0.dta directly against link1930_1940_ml1940_cleaned_noraceblock0.dta.

### 2. 4.82 million divided-file records absent from census1940_all_labeled_data.dta are coded as non-targets and switched to Ancestry names during matching

`unlabeled-divided-records-coded-as-nontarget` · **MAJOR** · identification · confidence: **verified** (traced in source)

**Where:** `MATCHING/1c_tgt_divided_files.do:17-19, MATCHING/1c_tgt_divided_files.do:52-65, MATCHING/1c_tgt_divided_files.do:100-114, MATCHING/tgt_fallback_diag.do:8-9, review/briefs/2026-11-17-tgt-diag.md:3`

**What the code does**  
MATCHING/1c_tgt_divided_files.do:52-65 builds tgt_flag1940.dta from census1940_all_labeled_data.dta using gen byte tgt = !(namefrst==namefrst_fs & namelast==namelast_fs) and keeps only tgt==1. Lines 100-101 merge this flag onto each 1940 divided file and set replace tgt = 0 if _merge==1, and lines 111-114 overwrite f_name, l_name, and mi_true_cleaned with _ans_cleaned values whenever !tgt. As documented in MATCHING/tgt_fallback_diag.do:8-9, 4,819,575 of the 66,135,592 divided-file records are not in census1940_all_labeled_data.dta at all.

**Why it matters**  
For these 4,819,575 records, commercial transcription agreement between Ancestry and FamilySearch is unmeasured, yet _tgt_cleaned forces them to use Ancestry names while _true_cleaned (ml1940) gives them model names. Even though downstream linkage tables restrict the denominator to the 51,036,859 labeled men aged 10+, Stage 2 (MATCHING/2_ABE_matchingV3_christian_torben.do:158-167) runs abematch on the full 66.1M divided-file universe first. Because abematch enforces name uniqueness within +-2 years of age (unique_m(2) unique_f(2)), switching 4.82M unmeasured records between model and Ancestry names changes candidate competition and match uniqueness for records inside the 51.0M analysis sample.

**How to check**  
Inspect the output of MATCHING/tgt_fallback_diag.do (MATCHING/results/tgt_fallback_diag.md) for the count of unmatched records aged 10+ (or aged 8+, which can compete within +-2 years of age 10). Test sensitivity by comparing links when those 4,819,575 records retain model names versus Ancestry names.

**Suggested fix**  
Document explicitly that divided-file records outside census1940_all_labeled_data.dta are assigned Ancestry names in the target-only run, and check whether keeping model names on those records (which lack FamilySearch transcriptions to confirm agreement with Ancestry) materially changes linkage rates or uniqueness competition for the 51.0M analysis sample.

### 3. Permitted fallback discrepancies and incomplete diagnostic checks leave non-target name and middle-initial differences between runs

`fallback-tolerance-and-incomplete-diagnostic-confound-contrast` · **minor** · correctness · confidence: **verified** (traced in source)

**Where:** `MATCHING/1c_tgt_divided_files.do:105-115, MATCHING/1c_tgt_divided_files.do:128-136, MATCHING/tgt_fallback_diag.do:37, MATCHING/tgt_fallback_diag.do:58-77`

**What the code does**  
MATCHING/1c_tgt_divided_files.do:108-109 counts records with name_true_cleaned_exists==0 & !(f_name==f_ans & l_name==l_ans) into nbad (436 of 1,031,654 records) and lines 133-136 allow the build to proceed unless nbad > 0.001*nchk. For any discrepant record with !tgt, lines 111-114 overwrite f_name, l_name, and mi_true_cleaned with _ans_cleaned values in _tgt_cleaned, whereas _true_cleaned (ml1940) retains the differing _true_cleaned fallback values. In addition, neither 1c_tgt_divided_files.do:108 nor MATCHING/tgt_fallback_diag.do:37 checks whether mi_true_cleaned != mi_ans when name_true_cleaned_exists==0, and tgt_fallback_diag.do:58-77 neither classifies the 436 records by tgt status nor writes more than 60 of the 436 rows (local k = min(_N, 60) at line 72) to MATCHING/results/tgt_fallback_diag.md despite its header comment (lines 6-7) stating that it lists them.

**Why it matters**  
The stated purpose of rerunning _true_cleaned alongside _tgt_cleaned in MATCHING/_tgt_only_run.do:8-9 is so the two link files 'differ only in which 1940 records get model names'. Allowing fallback discrepancies on !tgt records causes the two runs to differ on records where the model gave no name, and any unchecked mi_true_cleaned != mi_ans fallback discrepancy alters Stage 3 middle-initial validation rates (3_append_and_clean_all_links_christian_torbenV2.do:129-134). Without classifying the 436 records by tgt or checking mi_true_cleaned in tgt_fallback_diag.do, the diagnostic report does not give the full reconciliation needed.

**How to check**  
In MATCHING/tgt_fallback_diag.do, merge tgt_flag1940.dta onto the discrepant records and run: (1) tab tgt if name_true_cleaned_exists==0 & !(f_name==f_ans & l_name==l_ans), and (2) count if name_true_cleaned_exists==0 & mi_true_cleaned!=mi_ans.

**Suggested fix**  
In MATCHING/tgt_fallback_diag.do, include mi_true_cleaned!=mi_ans in the fallback check, merge tgt_flag1940.dta to tabulate discrepancies by target status (tgt==1 vs tgt==0), and write all 436 rows (or a separate CSV/DTA) rather than truncating the markdown table at 60 rows. Harmonize the fallback cleaning before producing final paper exhibits.
