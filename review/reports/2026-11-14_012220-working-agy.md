### 1. Profile-name analysis and runner script are omitted from the replication pipeline and rely on unconfigured paths

`profile-analysis-outside-replication-pipeline` · **MAJOR** · replication · confidence: **verified** (traced in source)

**Where:** `replication/run_machineA.do:92-95, replication/run_machineA.do:120-132, MATCHING/profile_names_score.do:37-39, MATCHING/_run_profile_names_score.do:1-2, MATCHING/profile_names_build.do:27-28`

**What the code does**  
replication/run_machineA.do orchestrates the replication suite for the paper's exhibits but omits MATCHING/profile_names_build.do and MATCHING/profile_names_score.do. The only launcher provided is the untracked script MATCHING/_run_profile_names_score.do, which hardcodes D:\repos\..., while MATCHING/profile_names_build.do hardcodes the raw profile scrapes to E:/multigen_CM/DATA/INTERMEDIATE without a corresponding configuration entry in replication/config.do.

**Why it matters**  
An independent replicator executing run_machineA.do cannot build profile_names.dta or produce MATCHING/results/profile_names.md, which underlies the appendix table on transcription accuracy. The appendix results remain an out-of-band workflow that can easily drift out of sync with the main analysis.

**How to check**  
Inspect replication/run_machineA.do and confirm that neither MATCHING/profile_names_build.do nor MATCHING/profile_names_score.do is invoked, and check replication/config.do to confirm that the profile scrapes directory on E: is not defined.

**Suggested fix**  
Add a path global for profile data to replication/config.do, add profile_names_build.do and profile_names_score.do to replication/run_machineA.do (or a dedicated appendix replication runner), and ensure all scripts use $REP_REPO rather than hardcoded D:\ paths.

### 2. MATCHING/_run_profile_names_score.do swallows execution failures with capture noisily without propagating return code

`standalone-launcher-swallows-errors` · **minor** · correctness · confidence: **verified** (traced in source)

**Where:** `MATCHING/_run_profile_names_score.do:1-2`

**What the code does**  
The script executes `capture noisily do "D:\repos\fixing_transcription_errors\MATCHING\profile_names_score.do"` and then `display "RUN-STATA-RC: " _rc` without checking `if _rc exit _rc`. Consequently, Stata terminates with exit code 0 even if profile_names_score.do aborts with an error.

**Why it matters**  
In automated batch execution or CI pipelines, any failure in profile_names_score.do (such as missing inputs, merge assertion failures, or missing Stata dependencies) will be reported as a successful run, silently leaving stale or missing output files unnoticed.

**How to check**  
Run stata -b do MATCHING/_run_profile_names_score.do under a failure condition (e.g. rename profile_names.dta temporarily) and inspect the shell exit status in PowerShell with $LASTEXITCODE; it returns 0 despite the failure.

**Suggested fix**  
Propagate the Stata return code by adding `if _rc exit _rc` after line 2, and use $REP_REPO rather than a hardcoded absolute path.

### 3. User-written Stata command extrname is not vendored in replication/stata or documented in setup instructions

`extrname-dependency-not-vendored-or-documented` · **minor** · replication · confidence: **verified** (traced in source)

**Where:** `MATCHING/profile_names_score.do:78, replication/stata/repnum.ado`

**What the code does**  
MATCHING/profile_names_score.do calls the user-written command `extrname` at line 78. Unlike repnum.ado, which is vendored in replication/stata/, extrname is neither vendored in the repository nor documented in replication/README.md.

**Why it matters**  
A replicator running the script on a standard Stata installation will encounter error 199 (unrecognized command: extrname). Because extrname is an archival package from STB-13 (1993) rather than an SSC package, resolving the dependency is non-trivial without documentation.

**How to check**  
In a clean Stata environment without STB packages installed, execute `which extrname`. It will return error 111 (command not found).

**Suggested fix**  
Vendor extrname.ado and extrname.hlp in replication/stata/ alongside repnum.ado (which is automatically added to the adopath by config.do), or add explicit installation instructions for STB-13 dm13 in replication/README.md.
