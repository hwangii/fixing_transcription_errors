### 2. Machine-specific hostname gating and hardcoded drive paths prevent execution in external environments

`hostname-lock-and-hardcoded-paths` · **MAJOR** · replication · confidence: **verified** (traced in source)

**Where:** `replication/config.do:19-41,replication/hash_inputs.py:96-97,replication/hash_inputs_machineB.py:83-84,replication/check_claims.py:296-300,replication/run_machineA.do:25,replication/run_machineB.do:29,replication/Run-Stata.ps1:22`

**What the code does**  
config.do checks c(hostname) against 'ARTS-ECON-CM' and 'ARTS-ECON-SHSRV' and throws error 198 on any other machine. hash_inputs.py, hash_inputs_machineB.py, and check_claims.py also exit immediately if the hostname does not match. run_machineA.do and run_machineB.do hardcode absolute paths 'D:/repos/...' and 'F:/github_repos/...'. Run-Stata.ps1 hardcodes 'C:\Program Files (x86)\Stata15\StataMP-64.exe'.

**Why it matters**  
An external replicator cannot run preflights, manifest checks, or do-files without modifying configuration files and script headers.

**How to check**  
Run 'stata -b do replication/config.do' on any computer whose hostname is not ARTS-ECON-CM or ARTS-ECON-SHSRV; it halts with r(198) at line 40.

**Suggested fix**  
Replace hardcoded hostname checks in config.do with configurable base-path globals or environment variables, remove hostname exit checks in hash scripts, pass --paper-repo dynamically in PowerShell runners, and make Stata executable paths configurable.

### 3. Genealogical truth set shares FamilySearch provenance with model's dominant agreement source

`familysearch-validation-circularity` · **MAJOR** · identification · confidence: **likely** (implied, depends on unseen data)

**Where:** `D:/repos/6638fa0fd89fbec05130caeb/DHTS-2026-10-12.tex:573-581,D:/repos/6638fa0fd89fbec05130caeb/DHTS-2026-10-12.tex:301-305`

**What the code does**  
The paper validates link quality against mlp_training1930_1940.dta derived from FamilySearch genealogical trees, while Section 3 notes the model agrees with FamilySearch 52% of the time vs 14% with Ancestry on discordant records.

**Why it matters**  
Because FamilySearch user trees frequently rely on FamilySearch's transcription index, an ML transcription that strongly aligns with FamilySearch will mechanically validate at higher rates against FamilySearch trees, confounding genuine match quality with shared source errors.

**How to check**  
Tabulate in validation_by_link_status.do or deaglan_abe_jw.tex whether the links verified correct by the genealogical truth set are disproportionately those where the ML transcription agrees with FamilySearch against Ancestry.

**Suggested fix**  
Disclose and discuss the shared FamilySearch provenance in Section 4.2, report sensitivity of validation rates to FamilySearch agreement, and benchmark against a non-FamilySearch ground truth where feasible.

### 6. PowerShell automation drivers invoke claim checker without passing configured paper repository path
