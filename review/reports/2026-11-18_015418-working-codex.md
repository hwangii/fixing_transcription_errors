### 1. Target mode constructs the wrong link filename and stops before producing figures

`target-link-stem-omits-cleaned` · **MAJOR** · correctness · confidence: **verified** (traced in source)

**Where:** `CODE/create_figures_SSHA2025.do:30-38, CODE/create_figures_SSHA2025.do:95-98, MATCHING/3_append_and_clean_all_links_christian_torbenV2.do:88-89, MATCHING/3_append_and_clean_all_links_christian_torbenV2.do:149, MATCHING/score_tgt_links.do:39-42`

**What the code does**  
When `FIG_NEWLINKS` is `mltgt1940`, the code assigns `local newv "$FIG_NEWLINKS"` and requests `link1930_1940_`newv'_noraceblock0.dta`, yielding `link1930_1940_mltgt1940_noraceblock0.dta`. The producer instead constructs version `_mltgt1940` and then appends `_cleaned`, and the scorer explicitly opens `link1930_1940_mltgt1940_cleaned_noraceblock0.dta`.

**Why it matters**  
The target-mode merge encounters a nonexistent using file and terminates before writing `temp_tgt.dta`, the target PDFs, or substantive replication numbers. Because `repnum open` occurs earlier, it can also leave a header-only target results file that looks like an attempted output.

**How to check**  
Run `Test-Path 'D:/SNU ECON Dropbox/sam hwang/enum_date/DATA/INTERMEDIATE/link1930_1940_mltgt1940_noraceblock0.dta'` and the same command with `mltgt1940_cleaned`; only the latter should exist. Alternatively, run `confirm file` on both names in Stata.

**Suggested fix**  
Keep the accepted switch value as `mltgt1940`, but set the target link stem to `mltgt1940_cleaned` before interpolating it into the path, for example with a separate `local newv "mltgt1940_cleaned"`. Preserve `true_cleaned` in the default branch.

### 2. The analysis closes the batch log that Run-Stata uses to detect completion

`batch-log-closed-before-completion-marker` · **MAJOR** · replication · confidence: **verified** (traced in source)

**Where:** `CODE/create_figures_SSHA2025.do:1, CODE/create_figures_SSHA2025.do:348-389, MATCHING/_figs_tgt_run.do:8-18, replication/Run-Stata.ps1:35-38, replication/Run-Stata.ps1:55-66`

**What the code does**  
The documented runner starts Stata in batch mode and recognizes completion only when its outer wrapper writes `RUN-STATA-RC:` into `_run__figs_tgt_run.log`. The first inner command is `capture log close`, which closes that unnamed batch log; the script later opens and closes a different unnamed log but never reopens the batch log before the outer wrapper displays the marker.

**Why it matters**  
The Stata work may finish or fail, but Run-Stata cannot observe either outcome. With `/b` still waiting after execution, the PowerShell runner can wait for its 600-minute default timeout and then kill Stata, reporting a timeout instead of the real return code.

**How to check**  
Run `powershell -File replication/Run-Stata.ps1 -DoFile MATCHING/_figs_tgt_run.do -TimeoutMinutes 1` with the current path error present. Inspect `MATCHING/_figs_tgt_run.log`; it will lack `RUN-STATA-RC:` after the inner `log close`, so the runner times out rather than reporting the immediate Stata error.

**Suggested fix**  
Preserve the batch log. Remove the blanket `capture log close`, and give the pipe-delimited socio-demographic log a name via `log using ..., name(...)`; use the same name for `log on`, `log off`, and `log close` so it can coexist with Run-Stata's unnamed batch log.

### 3. Target mode still replaces shared graph and log intermediates without the target suffix

`target-mode-overwrites-unsuffixed-intermediates` · **minor** · replication · confidence: **verified** (traced in source)

**Where:** `CODE/create_figures_SSHA2025.do:263-296, CODE/create_figures_SSHA2025.do:348-395, CODE/create_figures_SSHA2025.do:413-421`

**What the code does**  
Final exports interpolate `sfx`, but the graph saves remain `saving(1.gph,replace)` and `saving(2.gph,replace)`, while the data-bearing log remains `all_states_effect_socio_demo.log`, opened with `replace` and then imported. These paths are identical in default and target modes.

**Why it matters**  
The stated isolation guarantee is incomplete. A target run overwrites the default socio-demographic intermediate, and overlapping default and target runs can read each other's log or graph files, contaminating plotted values despite distinct final PDF names.

**How to check**  
Run `rg -n 'saving\(|log using|graph export|file open|save ' CODE/create_figures_SSHA2025.do` and compare each write path with the `sfx` assignments. The `1.gph`, `2.gph`, and `all_states_effect_socio_demo.log` writes are the unsuffixed exceptions.

**Suggested fix**  
Add `sfx` to the socio-demographic log path and to every saved/read `.gph` path, including the `grc1leg` and `graph combine` inputs. Prefer temporary files for the `.gph` intermediates so caller working directories cannot create collisions.
