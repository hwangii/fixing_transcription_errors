## Findings

### 1. The reported 28% match-quality improvement changes the validator between before and after

`moving-validator-inflates-match-quality` · **BLOCKER** · claims-vs-code · confidence: **verified** (traced in source)

**Where:** `CODE/create_figures_SSHA2025.do:70-83, D:\repos\6638fa0fd89fbec05130caeb\DHTS-2026-10-12.tex:68, D:\repos\6638fa0fd89fbec05130caeb\DHTS-2026-10-12.tex:98, D:\repos\6638fa0fd89fbec05130caeb\DHTS-2026-10-12.tex:547-549, replication/results/validation_fixed_initials.tex:28-30, replication/results/validation_fixed_initials.tex:68-70`

**What the code does**  
The old links set `validated_before=mi1930==mi1940` using `mi1940` from the Ancestry-name link file, while the new links independently set `validated_after=mi1930==mi1940` using `mi1940` from the model-name link file. Thus `100*(sv_after/sv_before-1)` changes both the links and the 1940 initial used to judge them. The paper describes the resulting 28% as improved link or match quality, even though the fixed-validator diagnostic reports only 16.0% with one Ancestry initial and 11.5% with one FamilySearch initial.

**Why it matters**  
The abstract and main results report 28% as a headline improvement and infer that the new links are true rather than spurious. A same-person link can change validation status solely because its 1940 initial was retranscribed; that is not a change in link correctness. The existing diagnostic records 165,580 kept links whose validation changes, so this is material rather than hypothetical.

**How to check**  
Run `replication/diagnostics/validation_fixed_initials.do` after a full rebuild and compare `valGainTarget` with `valGainAncTarget` and `valGainFsTarget`. Also tabulate `validated_before validated_after if linked_before==1 & linked_after==1 & id_A_before==id_A_after, missing`; any off-diagonal observations prove that the purported link-quality measure changes while the linked pair is unchanged.

**Suggested fix**  
Use one fixed 1940 middle-initial source for both link vintages in the main table, report that source explicitly, and show the other human transcription as robustness. Revise the abstract and lines 98 and 548 to the fixed-validator estimate; if the moving measure is retained, label it as a combined change in links and middle-initial transcription rather than match quality.

### 2. The new decomposition counts rescoring of switched links as a linkage-composition effect

`switched-links-contaminate-decomposition` · **MAJOR** · correctness · confidence: **verified** (traced in source)

**Where:** `replication/diagnostics/validation_by_link_status.do:85-109, replication/diagnostics/validation_by_link_status.do:27-31`

**What the code does**  
The counterfactual starts with `gen byte v_cf = validated_after if linked_after==1` and substitutes the before score only when `status==1`, the kept-same-partner group. Switched links (`status==2`) retain `validated_after`, which uses both a different 1930 partner and the new link file’s different 1940 initial. Nevertheless, `ppLinks = 100*(cf-b)` is labeled as arising from only “which links exist,” while `ppRescoring = 100*(a-cf)` captures rescoring only among kept links.

**Why it matters**  
The proposed diagnostic will overattribute the 65%-to-84% rise to changed links and underattribute it to the moving validator. That makes it unsuitable for defending the central match-quality claim, especially because switched links are precisely observations for which both the partner and validator change.

**How to check**  
For after links, construct a counterfactual score using the after link’s `mi1930` but the same fixed 1940 initial used for the before links, including `status==2`. Compare this fixed score with `v_cf`, and separately tabulate the difference for `status==2`. Recompute `ppLinks` and `ppRescoring`; they should isolate partner composition and validator changes respectively.

**Suggested fix**  
Merge the underlying initials into this diagnostic and define the counterfactual for every after link as `mi1930_after == mi1940_fixed`, not as `validated_after`. Then compare before-fixed, after-fixed, and after-moving measures. State the decomposition order because changing denominators and missing-initial coverage makes component shares order-dependent.

### 3. The claim registry now validates the flawed statistic against itself after deleting the independent guard

**Where:** `replication/claims.toml:72-78, replication/claims.toml:355-369, replication/claims_report.md:17-19`

**Why it matters**

This converts a useful replication failure into a false clean bill of health without resolving the underlying measurement problem.

**How to check**

**Suggested fix**  
Restore fixed-validator assertions and explanatory issue notes for every affected claim. Keep them failing until the main calculation and paper use one fixed validator; do not make the automated check pass by removing the cross-check.
