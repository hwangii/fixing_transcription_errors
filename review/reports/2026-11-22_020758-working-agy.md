### 1. Fallback check in 1e adds mi_true_cleaned==mi_ans (which is empty on 1_divide fallbacks) and inflates nchk 162x with non-target records

`fallback-check-mi-and-denominator-in-1e` · **MAJOR** · correctness · confidence: **verified** (traced in source)

**Where:** `MATCHING/1e_tgtns_divided_files.do:77-81, MATCHING/1e_tgtns_divided_files.do:106-113`

**What the code does**  
Line 80 checks `quietly count if name_true_cleaned_exists==0 & !(f_name==f_ans & l_name==l_ans & mi_true_cleaned==mi_ans)` and line 112 exits with error 459 if `nbad > 0.001*nchk`, claiming `/*SAME TOLERANCE AS 1c (THE 436 KNOWN CASES, tgt_fallback_diag.do). NON-TARGET RECORDS WERE SET TO ANCESTRY BY 1c, SO THESE CAN ONLY BE TARGET RECORDS WITHOUT MODEL NAMES.*/`. However:
1. In `1c_tgt_divided_files.do:108`, the check was `!(f_name==f_ans & l_name==l_ans)` and did NOT test `mi_true_cleaned==mi_ans`. When `divided_file1940_true_cleaned` was built by `MATCHING/1_divide_and_clean_everyoneV5_women_addedV2.do:148-150,169-173`, line 150 loaded `namefrst_ans_cleaned` (from which the prior `abeclean` in `0_create_file_for_matching_intgenV4_women_added.do:87` had already stripped the middle-initial token into `mi`), not raw `namefrst_ans`. At `1_divide:169`, `namefrst_ans` abbreviated `namefrst_ans_cleaned`, so running `abeclean ..., initial(mi_true_cleaned)` a second time on the single-token `namefrst_ans_cleaned` at `1_divide:173` set `mi_true_cleaned = ""` on every record where `namefrst_ml == ""` fell back to Ancestry.
2. In `divided_file1940_tgt_cleaned`, `1c_tgt_divided_files.do:111-114` overwrote `mi_true_cleaned = mi_ans` and `name_true_cleaned_exists = 0` on all 48,860,469 non-target records (`!tgt`), but left the 302,053 target records without model names (`MATCHING/_tgt_only_run.log:3893`) with `mi_true_cleaned == ""`. Every one of those 302,053 target fallback records that has a non-empty Ancestry middle initial `mi_ans != ""` (~20-31% of records, or ~60,000-95,000 records) therefore fails `mi_true_cleaned==mi_ans` and is counted in `nbad`.
3. Meanwhile, `nchk` (`count if name_true_cleaned_exists==0`, line 78) sums all 48,860,469 non-target records (which cannot fail because `1c` set them to `_ans_cleaned`) plus the 302,053 target fallback records (`49,162,522` total), making `0.001*nchk = 49,162.5` (16.3% of the 302,053 tested records rather than 0.1%).

**Why it matters**  
Because ~60,000-95,000 of the 302,053 target records with `name_true_cleaned_exists==0` have a non-empty `mi_ans` while `mi_true_cleaned==""`, `nbad` is likely to exceed `0.001*nchk` (`49,162.5`) and abort `MATCHING/_tgtns_run.do` with `exit 459` at line 112 after all 139 files in `divided_file1940_tgtns_cleaned` have already been written (which then blocks a rerun with `exit 602` until the folder is deleted). Furthermore, in `divided_file1940_tgtns_cleaned`, target records with `namefrst_ml=="InvalidPred"` get `mi_true_cleaned = mi_ans` (line 95), whereas target records with `namefrst_ml==""` got `mi_true_cleaned = ""` in `1_divide`, creating an asymmetry in the 1940 middle initial used by `Share validated, MI (%)` (`sv`) and `Links with both initials` (`nv`) in `MATCHING/score_tgt_links.do:236-241`.

**How to check**  
In Stata, load one shard of divided_file1940_tgt_cleaned and divided_file1940_ans_cleaned (e.g. norace1.dta), merge 1:1 on id, and run:
count if name_true_cleaned_exists==0 & mi_ans!=""
count if name_true_cleaned_exists==0 & mi_true_cleaned!=mi_ans
This will show that on target records with name_true_cleaned_exists==0, mi_true_cleaned is empty ("") even when mi_ans is non-empty.

**Suggested fix**  
1. In MATCHING/1e_tgtns_divided_files.do:80, either match 1c_tgt_divided_files.do:108 by checking only `!(f_name==f_ans & l_name==l_ans)` (or also repair `mi_true_cleaned = mi_ans` on target records where the first name fell back to Ancestry), and count `nchk` over target fallback records only (excluding the 48.86M non-target records that 1c overwrote with _ans_cleaned) so the 0.1% threshold has the same denominator and meaning as 1c.
2. Decide whether target records whose raw `namefrst_ml` was empty (`""`) should also take `mi_ans` (like `sf==1` records at line 95), so empty-string and `"InvalidPred"` first-name fallbacks have identical middle-initial treatment in `score_tgt_links.do`.

### 2. name_true_cleaned_exists stays 1 when one model field was 'InvalidPred' and the other was already empty

`single-sentinel-plus-empty-field-leaves-exists-flag-one` · **minor** · claims-vs-code · confidence: **verified** (traced in source)

**Where:** `MATCHING/1e_tgtns_divided_files.do:14-23, MATCHING/1e_tgtns_divided_files.do:83-97`

**What the code does**  
The header at `MATCHING/1e_tgtns_divided_files.do:14-23` claims that replacing `"invalidpred"` in `divided_file1940_tgt_cleaned` `"equals blanking the sentinel before the fallback, because: ... a record with BOTH fields 'invalidpred' would have had no model name at all (1_divide keeps a model row only if a field is non-empty), so its name_true_cleaned_exists becomes 0"`, and line 97 runs `replace name_true_cleaned_exists = 0 if sf & sl`. However, when a target record had ONE raw model field equal to `"InvalidPred"` and the OTHER equal to `""` (empty), `MATCHING/1_divide_and_clean_everyoneV5_women_addedV2.do:119,165,169-170` kept the row (because `"InvalidPred" != ""`), set `name_true_cleaned_exists = 1`, and replaced the empty field with Ancestry's name before `abeclean`. In `divided_file1940_tgt_cleaned`, that already-replaced field equals `f_ans` or `l_ans` (not `"invalidpred"`), so `sf & sl` is 0. After lines 94-96 replace the `"invalidpred"` field with Ancestry's name, neither name field comes from the model, yet line 97 leaves `name_true_cleaned_exists == 1` (whereas blanking `"InvalidPred"` before `1_divide:119` would have dropped the row from `temptemptemp` and produced `name_true_cleaned_exists == 0`). From `MATCHING/results/ditto_diag.md:52,56`, there are `3,375,771 + 298,969 - 3,659,075 = 15,665` such target records across the 49 model states.

**Why it matters**  
Neither `abematch` (`MATCHING/2_ABE_matchingV3_christian_torben.do:152,158`), `MATCHING/3_append_and_clean_all_links_christian_torbenV2.do:118-144`, nor `MATCHING/score_tgt_links.do` reads `name_true_cleaned_exists`, so ABE linkage and the numbers in `MATCHING/results/tgt_linkage_abe.md` are unaffected. However, `name_true_cleaned_exists` is saved in `divided_file1940_tgtns_cleaned/norace*.dta` (`1e:101-103`) and remains `1` on ~7,500 male target records that carry only Ancestry fallback names, contradicting the header claim at lines 14-23 and affecting any downstream script that uses `name_true_cleaned_exists == 1` to identify records with usable model output.

**How to check**  
In `MATCHING/results/ditto_diag.md:52,56`, compare `fail_raw` (3,375,771), `tgt_ip` (298,969), and `fail_pre` (3,659,075): by inclusion-exclusion, `3,375,771 + 298,969 - 3,659,075 = 15,665` target records in the 49 model states have one field equal to `"InvalidPred"` and the other field equal to `""`. On the male divided-file subset of these 15,665 records, `sf + sl == 1` (`sf & sl == 0`), so `name_true_cleaned_exists` remains 1 after `1e_tgtns_divided_files.do:97`.

**Suggested fix**  
Either update the header comment at `MATCHING/1e_tgtns_divided_files.do:21-23` to note that `name_true_cleaned_exists` is only cleared when both fields were `"invalidpred"` (since `_tgt_cleaned` does not record whether the non-sentinel field came from the model or from `1_divide`'s empty-string Ancestry fallback), or merge the raw `namefrst_ml` and `namelast_ml_ditto` presence indicators if `name_true_cleaned_exists` in `divided_file1940_tgtns_cleaned` needs to be exact.
