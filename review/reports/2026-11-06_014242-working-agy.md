## Findings

### 1. The new FamilySearch linking pipeline depends on ABE commands that are not placed on Stata's ado-path

`abe-commands-not-on-adopath` · **MAJOR** · replication · confidence: **verified** (traced in source)

**Where:** `MATCHING/1b_fs_divided_files.do:65, MATCHING/2_ABE_matchingV3_christian_torben.do:44, MATCHING/2_ABE_matchingV3_christian_torben.do:158, replication/config.do:44`

**What the code does**  
MATCHING/1b_fs_divided_files.do:65 directly calls `abeclean` and MATCHING/2_ABE_matchingV3_christian_torben.do:158 calls `abematch`. However, replication/config.do:44 only adds `$REP_REPO/replication/stata` (which contains only repnum.ado) to the ado-path, and assigning `global MatchingDoFiles` in MATCHING/2_ABE_matchingV3_christian_torben.do:44 points to an external Dropbox folder without issuing an `adopath ++` command.

**Why it matters**  
An external replicator running the master matching script or placebo check on a clean checkout will fail immediately with unrecognized command errors for abeclean and abematch. The pipeline cannot be reproduced self-contained from the repository.

**How to check**  
In a fresh Stata session where PERSONAL and PLUS directories do not already contain ABE commands, run `do replication/config.do` followed by `which abeclean` and `which abematch`. Both will return error 111 ('command not found') despite copies existing under LINKAGE/code/01_abe_jw/.

**Suggested fix**  
Add the repository ABE implementation to the ado-path in replication/config.do (e.g. `adopath ++ "$REP_REPO/LINKAGE/code/01_abe_jw/reference"`), or copy abeclean.ado, abematch.ado, and their dependencies into replication/stata/.

### 2. FamilySearch divided files are reused solely based on filename presence without checking contents or inputs

`filename-only-divided-file-cache` · **minor** · replication · confidence: **verified** (traced in source)

**Where:** `MATCHING/_matching_master_dofile.do:87-94`

**What the code does**  
MATCHING/_matching_master_dofile.do:87-94 compares the list of filenames `built` in `divided_file<y><fstype>` against `want` in `divided_file<y>_ans_cleaned`. If the filename lists match, it assumes the divided directory is complete and skips running 1b_fs_divided_files.do.

**Why it matters**  
If an earlier run was aborted midway leaving corrupted files, or if fs_names<yr>.dta or the cleaning code in 1b_fs_divided_files.do is altered, subsequent linking runs silently reuse obsolete intermediate files. Link counts may depend on leftover disk artifacts.

**How to check**  
Modify fs_names1930.dta or touch/truncate a norace*.dta file in divided_file1930_fs_cleaned, then run _matching_master_dofile.do. It will report 'divided_file1930_fs_cleaned complete: reused' without rebuilding.

**Suggested fix**  
Check timestamps or hashes against the underlying inputs (fs_names<yr>.dta and the cleaning script), or introduce a force-rebuild parameter to ensure stale or corrupted intermediate files are not silently reused.
