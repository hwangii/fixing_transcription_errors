Commit range 5620c2b..HEAD introduces diagnostic scripts demonstrating that the paper's headline 28 percent match-quality gain (and 1 percent overall gain) was largely an artifact of shifting the 1940 middle-initial transcription between link files rather than true link recovery. ## Findings

### 1. The paper's headline 28 percent match-quality gain is contradicted by the new fixed-validator diagnostic

`paper-match-quality-gain-contradicted-by-fixed-validator` · **BLOCKER** · claims-vs-code · confidence: **verified** (traced in source)

**Where:** `replication/diagnostics/validation_fixed_initials.do:63-80, replication/results/validation_fixed_initials.tex:10-26, DHTS-2026-10-12.tex:98, DHTS-2026-10-12.tex:548, DHTS-2026-10-12.tex:551, figures/avg_performance_allstates.tex:10-11`

**What the code does**  
The paper reports that match quality (share of links validated by matching middle initials) increased from 65% to 84%, a 28 percent improvement in the target group (lines 98, 548) and by 1 percent overall (line 551). The upstream analysis in CODE/create_figures_SSHA2025.do:73,83 produced this by evaluating links before using Ancestry's 1940 middle initial and after using a different 1940 middle initial from the new link file. The new diagnostic in replication/diagnostics/validation_fixed_initials.do:63-80 rescores both link versions against a single fixed 1940 middle initial from Ancestry or FamilySearch. Under Ancestry's fixed initial, target-group validation rises from 64.3% to 74.5% (a 16.0% gain, raw=15.96%), and all-records validation is essentially flat at 84.86% to 84.91% (a 0.1% gain, raw=0.067%). Under FamilySearch's fixed initial, target validation rises from 72.9% to 81.3% (an 11.5% gain, raw=11.51%), and all-records validation rises by 0.6%.

**Why it matters**  
The paper claims a 28 percent increase in match quality as one of its three headline findings in the abstract and results section. The committed results in validation_fixed_initials.tex prove that nearly half of the target-group gain (and essentially all of the 1% overall gain) was driven by changing the measuring instrument between files rather than true link quality improvement.

**How to check**  
Compare \valGainTarget (28%) and \valGainAll (1%) in replication/results/create_figures_SSHA2025.tex against \valGainAncTarget (16.0%), \valGainFsTarget (11.5%), \valGainAncAll (0.1%), and \valGainFsAll (0.6%) in replication/results/validation_fixed_initials.tex.

**Suggested fix**  
Update draft lines 98, 548, and 551, along with Table 1 (figures/avg_performance_allstates.tex), to report validation gains under a consistent fixed middle initial (16.0% under Ancestry or 11.5% under FamilySearch for the target group; 0.1% or 0.6% overall), and state explicitly that the validator is held constant across link versions.

### 2. The automated claims checker gives false assurance because validation claims remain wired to the stale, disproven result file

`claims-checker-unwired-to-fixed-validator-results` · **MAJOR** · replication · confidence: **verified** (traced in source)

**Where:** `replication/claims.toml:55-75, replication/claims.toml:355-361, replication/claims_report.md:10, replication/claims_report.md:41, replication/claims_report.md:62, replication/results/validation_fixed_initials.tex:5-26`

**What the code does**  
In replication/claims.toml:355-361, claim results-validated ('increased from 65\\% to 84\\%, a 28 percent improvement') and intro-val-gain ('28 percent increase in match quality') are mapped exclusively to valGainTarget and shareValTargetBefore/After from create_figures_SSHA2025.tex. Although validation_fixed_initials.tex is read by check_claims.py (claims_report.md:10), none of its macros (valGainAncTarget, valGainFsTarget) are checked in claims.toml. Consequently, check_claims.py reports 50 MATCH / 0 FAIL, certifying the draft claims against the superseded file while ignoring the diagnostic that disproved them.

**Why it matters**  
The replication test suite serves to catch discrepancies between the text and empirical calculations. Leaving validation claims wired to the old file provides false confidence that the paper's headline 28% match quality claim is replicated and valid.

**How to check**  
Run python replication/check_claims.py --paper-repo D:/repos/6638fa0fd89fbec05130caeb. It reports MATCH for results-validated and intro-val-gain using create_figures_SSHA2025.tex while none of the validation_fixed_initials.tex macros are evaluated.

**Suggested fix**  
Wire results-validated and intro-val-gain in replication/claims.toml to the macros generated by validation_fixed_initials.tex (or update create_figures_SSHA2025.do to use the fixed initial), so that the checker alerts the authors until the text is aligned with the fixed-initial results.

### 3. validation_fixed_initials.do omits Kept and Switched link validation and fails to export sample counts and initial availability

`fixed-validator-omits-kept-switched-and-sample-counts` · **MAJOR** · correctness · confidence: **verified** (traced in source)

**Where:** `replication/diagnostics/validation_fixed_initials.do:71-88, replication/results/validation_fixed_initials.tex:1-27, replication/diagnostics/validation_by_link_status.do:59-75`

**What the code does**  
In replication/diagnostics/validation_fixed_initials.do:81-88, the loop only summarizes and exports Added and Dropped links, omitting Kept (status 1) and Switched (status 2). Additionally, although non-missing counts are computed in locals nb, na, and nn (lines 73, 76, 85), none of the link sample sizes, counts with non-missing initials, or initial coverage percentages (pctMi) are exported to validation_fixed_initials.tex, unlike in validation_by_link_status.do:71-74.

**Why it matters**  
Kept links constitute the large majority of linked records. Without exporting Kept validation under fixed initials, readers cannot see the invariant anchor uniting the before and after rates. Omitting the counts also conceals that fixed-initial validation is evaluated on only ~20-25% of linked records with observed initials.

**How to check**  
Examine replication/results/validation_fixed_initials.tex. It contains only rate macros (val*) and agreement shares (agree*), completely lacking any n*, nMi*, or pctMi* macros or Kept/Switched categories.

**Suggested fix**  
In replication/diagnostics/validation_fixed_initials.do, add Kept and Switched to the loop at line 81, and export n, nMi, and pctMi using repnum for all status categories and samples, matching validation_by_link_status.do.

### 4. Middle-initial parsing treats generational suffixes like 'Jr' and 'II' as middle initials without filtering

`middle-initial-extraction-includes-name-suffixes` · **minor** · correctness · confidence: **verified** (traced in source)

**Where:** `replication/diagnostics/validation_fixed_initials.do:23-27`

**What the code does**  
Line 25 extracts the first character of the second word in the first-name field: gen mi_\`src' = lower(substr(word(strtrim(\`v'), 2), 1, 1)), and line 26 requires only that it be a letter [a-z]. For names containing generational suffixes in the second position (e.g. 'John Jr', 'William II'), this extracts 'j' or 'i' as the middle initial.

**Why it matters**  
Individuals with generational suffixes are assigned bogus middle initials, contaminating middle-initial validation comparisons between 1930 and 1940 records.

**How to check**  
Run count if inlist(lower(word(strtrim(namefrst), 2)), "jr", "sr", "ii", "iii", "iv") in temp.dta to verify the number of records where a generational suffix is parsed as a middle initial.

**Suggested fix**  
In replication/diagnostics/validation_fixed_initials.do:26, add a condition to set mi_\`src' = "" if inlist(lower(word(strtrim(\`v'), 2)), "jr", "sr", "ii", "iii", "iv").
