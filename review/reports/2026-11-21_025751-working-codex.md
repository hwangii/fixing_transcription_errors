## Findings

### 1. The tracked profile result is currently truncated because its generator overwrites it non-atomically

`profile-result-nonatomic-truncation` · **BLOCKER** · replication · confidence: **verified** (traced in source)

**Where:** `MATCHING/results/profile_names_jw.md:43-49, MATCHING/profile_names_jw.do:194-233, Sync.ps1:71-72`

**What the code does**  
`profile_names_jw.do` executes `file open md ..., write replace text` before entering the expensive six-specification loop and does not run `file close md` until every table is computed. The current tracked output ends at line 49 midway through the `disc` row (`| disc | ... | 4`), omitting the remainder of that table and the final two sections, rather than containing the six complete tables intended by lines 199-233.

**Why it matters**  
The repository currently contains an invalid reported result. Because `Sync.ps1 -Push` runs `git add -u`, it can stage and commit this partial tracked file while the Stata job is still running or after an interrupted run.

**How to check**  
Run `git --no-pager diff HEAD -- MATCHING/results/profile_names_jw.md`, `Get-Content MATCHING/results/profile_names_jw.md -Tail 5`, and `rg -n '^## ' MATCHING/results/profile_names_jw.md`. Confirm that the wrapper log ends with `RUN-STATA-RC: 0` and that all six sections are complete before committing.

**Suggested fix**  
Do not commit the result until the active job finishes successfully and all six tables are present. Make future generation atomic by writing to a temporary file, closing it after all calculations succeed, and only then replacing `MATCHING/results/profile_names_jw.md`.

### 2. The documented standalone diagnostic command is pinned to the author’s checkout path

`absolute-config-bootstrap` · **minor** · replication · confidence: **verified** (traced in source)

**Where:** `MATCHING/nomodel_diag.do:17, MATCHING/nomodel_diag.do:21-23, replication/Run-Stata.ps1:27-42`

**What the code does**  
The documented driver starts Stata in the do-file’s directory without defining `$REP_REPO`; the script then executes `do "D:/repos/fixing_transcription_errors/replication/config.do"`. A clone at any other location fails before reaching the centralized configuration.

**Why it matters**  
An external replicator must edit the analysis script itself merely to load the intended path configuration. This does not change the author’s current numbers, but it breaks the documented standalone replication route.

**How to check**  
Run `rg -n 'D:/repos|REP_REPO' MATCHING/nomodel_diag.do replication/Run-Stata.ps1` and compare the hardcoded path with `Run-Stata.ps1`’s working directory at line 42.

**Suggested fix**  
Load `../replication/config.do` relative to the working directory established by `Run-Stata.ps1`, or have the driver pass the resolved repository root; keep machine-specific roots inside `config.do`.
