## Findings

### 1. Unconditional save after `keep if sex==1` writes 0-observation shards for women-only birthplaces, causing `abematch` to abort with `exit 1`

`empty-men-birthplace-shard-breaks-abematch` · **BLOCKER** · correctness · confidence: **verified** (traced in source)

**Where:** `MATCHING/1f_v26_inputs.do:194-221`

**What the code does**  
In the loop over all 144 `norace*.dta` shards of `divided_file`yr'_women_added`, lines 194-221 run `preserve`, `keep if sex==1`, and unconditionally `save` `divided_file1940_v26_true_cleaned/`f'`, `divided_file1940_v26_tgt_cleaned/`f'`, and `divided_file`yr'_v26_ans_cleaned/`f'` even when `_N == 0`. In the original men-only pipeline (`MATCHING/0_create_file_for_matching_intgenV4_women_added.do:148-169`), `levelsof bpl` was taken after `keep if sex==1`, so birthplaces with only female records (`norace511.dta` in 1930 per `MATCHING/extract_diff_diag.log:2371,2383`, and 5 shards in 1940 including file #110 per `MATCHING/extract_diff_diag.log:1148-1150` and `MATCHING/check_mlp_abe_fname_diff.log:1131`) had no shard in the men-only directories.

**Why it matters**  
When `MATCHING/2_ABE_matchingV3_christian_torben.do:81-90,132-158` runs ABE matching on `divided_file1930_v26_ans_cleaned` and `divided_file1940_v26_{ans,true,tgt}_cleaned`, it sees `norace511.dta` (and any other 0-man shard present on disk alongside a partner shard in the other year) in both directories (`Aexists==1 & Bexists==1`) and calls `abematch`. Inside `abematch.ado:369-372` and `414-417`, `if _N == 0` triggers `noi di as error "File A has no non-missing ID vars."` (or `"File B has no non-missing ID vars."`) and `exit 1`, halting the entire ABE linkage run.

**How to check**  
Inspect MATCHING/extract_diff_diag.log:2371,2383 (showing norace511.dta exists in divided_file1930_women_added with 0 men) and MATCHING/check_mlp_abe_fname_diff.log:1131 (showing "(note: dataset contains 0 observations)" when loading sex==1 from a shard of divided_file1940_true_cleaned_women_added), or in Stata run `use "F:/enum_date/DATA/INTERMEDIATE/divided_file1930_women_added/norace511.dta" if sex==1, clear` followed by `count`, and compare with `C:\Program Files (x86)\Stata15\ado\base\a\abematch.ado:369-372,414-417`.

**Suggested fix**  
After `keep if sex==1` at MATCHING/1f_v26_inputs.do:195, wrap lines 197-220 in `if _N { ... }` so that birthplace shards with zero male observations are not written to `divided_file1930_v26_ans_cleaned` or `divided_file1940_v26_{ans,true,tgt}_cleaned` (while still retaining their female records in the MLP pieces at lines 223-232).

### 2. Non-empty raw model strings that `abeclean` strips to `""` bypass the pre-cleaning Ancestry fallback and leave empty linked names

`pre-abeclean-fallback-misses-strings-cleaned-to-empty` · **minor** · correctness · confidence: **likely** (implied, depends on unseen data)

**Where:** `MATCHING/1f_v26_inputs.do:108,167-175`

**What the code does**  
Lines 171-172 apply the Ancestry fallback (`replace namefrst_ml = namefrst_ans if namefrst_ml=="" & namefrst_ans!=""` and similarly for `namelast_ml_ditto`) before `abeclean` runs at line 173. In `abeclean.ado:173-211`, all non-letters (`[^a-z ]`) and standalone titles (`jr`, `sr`, `mr`, `mrs`, `dr`, `rev`, `sister`, `brother`, etc.) are stripped. Any model prediction that is non-empty raw (e.g., punctuation, digits, whitespace, or a standalone title) is not equal to `""` at lines 171-172, so it does not fall back to `namefrst_ans`/`namelast_ans`, and `abeclean` then turns `f_ml` or `l_ml` into `""` (Unlike `MATCHING/1b_fs_divided_files.do:79-87`, which cleans first and falls back when the cleaned field is empty).

**Why it matters**  
Any 1940 record whose raw model field contains only characters or titles removed by `abeclean` ends up with an empty `f_name` or `l_name` (`""`) in `divided_file1940_v26_true_cleaned`, `divided_file1940_v26_tgt_cleaned` (for target records), `for_mlp1940_v26.dta`, and `for_mlp1940_v26_tgt.dta` rather than Ancestry's non-empty cleaned name (`f_ans`/`l_ans`), preventing the record from linking or allowing `"" == ""` matches on the blank field.

**How to check**  
In Stata, after running line 175 of MATCHING/1f_v26_inputs.do on the 1940 shards (or on a single state's merged_data.dta passed through `abeclean`), run `count if f_ml=="" | l_ml==""` and `count if name_true_cleaned_exists & f_ml=="" & l_ml==""`.

**Suggested fix**  
After `rename (namefrst_ml_cleaned namelast_ml_ditto_cleaned) (f_ml l_ml)` at line 174, fall back to the already-cleaned Ancestry fields whenever `abeclean` strips a non-empty raw model string to empty (`replace mi_true_cleaned = mi if f_ml=="" & f_ans!=""`, `replace f_ml = f_ans if f_ml=="" & f_ans!=""`, `replace l_ml = l_ans if l_ml=="" & l_ans!=""`), or assert `f_ml != "" & l_ml != ""`.

### 3. `abeclean` 0.26 is neither vendored nor asserted (`nmar` is only displayed), and `hi/merged_data.dta` and `divided_file<yr>_women_added` are outside the input manifest

`unasserted-abeclean-version-and-unhashed-v26-inputs` · **minor** · replication · confidence: **verified** (traced in source)

**Where:** `MATCHING/1f_v26_inputs.do:24,64,67-68,89,121,154-155,234`

**What the code does**  
Line 64 runs `which abeclean` and lines 154-155 and 234 count and display `nmar` (`f_ans=="marshall" & !strpos(lower(namefrst_ans),"marsh")`) without asserting `nmar == 0`. Because `abeclean.ado` has no `*!` header line, `which abeclean` prints only the file path and not the version number, and `abeclean.ado` is not in `replication/stata/`. In addition, line 24 states `model table = 49 states' merged_data.dta`, whereas line 89 reads 50 folders (including `hi`), and neither `hi/merged_data.dta`, `divided_file{1930,1940}_women_added/norace*.dta`, nor `tgt_flag1940.dta` (built by `1c_tgt_divided_files.do`) is hashed in `replication/hash_inputs.py`.

**Why it matters**  
On a machine where an older `abeclean` (< 0.25) is installed on Stata's `adopath`, `1f_v26_inputs.do` will run to completion and exit 0 while silently writing the ~285-290k `"marshall"` corruptions into all `_v26` outputs. Leaving `hi/merged_data.dta` and `divided_file<yr>_women_added` out of `replication/hash_inputs.py` also means `python replication/hash_inputs.py --check` does not verify the inputs to `1f_v26_inputs.do`.

**How to check**  
Check MATCHING/marshall_diag.log:188-189 (`which abeclean` prints only `C:\Program Files (x86)\Stata15\ado\base\a\abeclean.ado` with no version string), list `replication/stata/` (`Get-ChildItem replication/stata`), and compare the 50 state folders in MATCHING/1f_v26_inputs.do:89 (which includes `hi`) against `replication/hash_inputs.py:68-80` and `replication/input_manifest.md:65-113`.

**Suggested fix**  
Vendor `abeclean.ado` (0.26) and `abematch.ado` (0.23) into `replication/stata/`, add `assert `nmar'==0` at line 234 (or a startup check asserting `abeclean` cleans `"lee"` to `"lee"`), update the comment at line 24 from `49 states'` to `50 jurisdictions' (including DC and HI)`, and add `hi/merged_data.dta` and `divided_file<yr>_women_added` to `replication/hash_inputs.py`.
