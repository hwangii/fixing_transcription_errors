## Findings

### 1. Positional varlist range `age-name_true_cleaned_exists` assumes `use <varlist> using` reorders variables in `for_mlp1940.dta`

`positional-varlist-range-in-compare-for-mlp-tgt` · **MAJOR** · correctness · confidence: **verified** (traced in source)

**Where:** `MATCHING/compare_for_mlp_tgt.do:26-32, MATCHING/1_divide_and_clean_everyoneV5_women_addedV2.do:165-253`

**What the code does**  
`MATCHING/compare_for_mlp_tgt.do:26-32` defines `local keepvars histid age sex bpl namefrst namelast mi namefrst_true_cleaned namelast_true_cleaned mi_true_cleaned name_true_cleaned_exists`, runs `use `keepvars' using `"`old'"', clear`, and then loops over `foreach v of varlist age-name_true_cleaned_exists` to rename every non-`histid` variable to `o_<var>`. However, Stata's `use <varlist> using <filename>` loads variables in their physical column order in `<filename>`, not the order listed in `<varlist>`. In `MATCHING/1_divide_and_clean_everyoneV5_women_addedV2.do:165-253`, which created the original `for_mlp1940.dta` without an `order` command, `histid` sits after `age`/`sex` (from the IPUMS extract before `namefrst`, `namelast`, `mi`, and `bpl`), and `name_true_cleaned_exists` (generated at line 165) precedes `namefrst_true_cleaned`, `namelast_true_cleaned`, and `mi_true_cleaned` (generated by `abeclean` at line 173). Consequently, `age-name_true_cleaned_exists` in `old` includes `histid` (renaming it to `o_histid`) and excludes variables positioned before `age` or after `name_true_cleaned_exists`.

**Why it matters**  
When `compare_for_mlp_tgt.do` runs against `for_mlp_original/for_mlp1940.dta`, renaming `histid` to `o_histid` causes `merge 1:1 histid using `o'` at line 38 to abort with `variable histid not found` (`r(111)`), and leaving any trailing `_true_cleaned` variables unrenamed in `o` would cause `merge` to silently retain `new`'s values for those variables and fail at line 62 with `o_namefrst_true_cleaned not found`.

**How to check**  
Run `describe using "F:/enum_date/DATA/INTERMEDIATE/for_mlp_original/for_mlp1940.dta"` in Stata (or run `MATCHING/compare_for_mlp_tgt.do`) and observe the variable order in `for_mlp1940.dta`: `histid` is not the first variable and `name_true_cleaned_exists` precedes `namefrst_true_cleaned`, `namelast_true_cleaned`, and `mi_true_cleaned`.

**Suggested fix**  
Replace `foreach v of varlist age-name_true_cleaned_exists` at `MATCHING/compare_for_mlp_tgt.do:30` with an explicit variable list (e.g., `foreach v in age sex bpl namefrst namelast mi namefrst_true_cleaned namelast_true_cleaned mi_true_cleaned name_true_cleaned_exists`) or add `order `keepvars'` immediately after `use `keepvars' using `"`old'"', clear`.
