## Findings

### 1. The non-target subtraction does not identify the effect of target-only replacement

`old-vs-new-does-not-identify-target-only-effect` · **MAJOR** · identification · confidence: **verified** (traced in source)

**Where:** `MATCHING/nontarget_from_tables.py:3-6, MATCHING/nontarget_from_tables.py:53-63, MATCHING/2_ABE_matchingV3_christian_torben.do:158-167`

**What the code does**  
MATCHING/nontarget_from_tables.py:59-63 subtracts target-sample linkage metrics (deaglan_abe_jw_restricted.tex, deaglan_hlink_restricted.tex) from all-record linkage metrics (deaglan_abe_jw.tex, deaglan_hlink.tex) for the global Old (all-Ancestry) and global New (all-Model) runs, then compares Old to New on the residual 36.6M non-target subset. The author intends to use this comparison to determine whether replacing names on all records rather than only on target records hurt linkage performance. However, both underlying tables are partitions of two global linkage runs: all-Ancestry names (Old) and all-Model names (New). The counterfactual policy—replacing names on target records only while leaving Ancestry names on non-target records—was never executed in those tables. Furthermore, in ABE matching (MATCHING/2_ABE_matchingV3_christian_torben.do:158-167), match uniqueness requires unique_file2 == 1 & unique_match2 == 1, so changing names on target records directly induces linkage spillovers and candidate competition that affect non-target matches.

**Why it matters**  
The observed decline in match rate (e.g., 28.30% to 26.64% for ABE exact) and verified links (5.41M to 5.10M) on non-target records under New conflates two mechanisms: using Model transcriptions on non-target records, and equilibrium linkage spillovers from altering target record names across the population. It cannot establish whether a target-only replacement strategy outperforms an all-records replacement strategy. Drawing policy or empirical conclusions about target-only replacement from this subtraction risks adopting the wrong transcription deployment strategy.

**How to check**  
Once MATCHING/_tgt_only_run.do finishes, compare link1930_1940_mltgt1940_cleaned_noraceblock0.dta directly against link1930_1940_ml1940_cleaned_noraceblock0.dta on the identical 36.6M non-target histid records. Directly tabulate matched pairs, verified links, and contradicted links between these two runs rather than differencing partitions of global Old vs New.

**Suggested fix**  
Label the All-minus-Target calculations in MATCHING/nontarget_from_tables.py strictly as a descriptive breakdown of how non-target records fared between the global Old and global New runs. To answer whether replacing names on all records hurts relative to replacing names only on target records, wait for and score the dedicated target-only linkage run (_tgt_only_run.do) against the all-new linkage run.

### 2. Reconstructed non-target recall reports false precision from rounded table rates

`rounded-recall-false-precision` · **minor** · correctness · confidence: **verified** (traced in source)

**Where:** `MATCHING/nontarget_from_tables.py:11-13, MATCHING/nontarget_from_tables.py:61-63`

**What the code does**  
Line 61 backs out the true link denominator as den = a['V'][j] / (a['rec'][j] / 100) - t['V'][j] / (t['rec'][j] / 100) and line 63 prints recall~ {100*V/den:5.2f}% formatted to two decimal places. The input recall values a['rec'][j] and t['rec'][j] from figures/deaglan_abe_jw.tex and figures/deaglan_abe_jw_restricted.tex are printed rounded to two decimal places (e.g. 31.69% and 11.13%).

**Why it matters**  
Inverting rounded percentages and differencing them propagates denominator uncertainty into the final quotient. For ABE exact Old, allowing the input recalls to vary within their rounding tolerance of +/-0.005 percentage points yields a non-target recall interval of approximately 38.571% to 38.599%. Printing 38.58% falsely implies two decimal digits of precision that are not identified by the published table inputs.

**How to check**  
Evaluate den across the extreme combinations where printed recall rates equal r - 0.005 and r + 0.005: den_min = V_all / ((rec_all + 0.005)/100) - V_tgt / ((rec_tgt - 0.005)/100) and den_max = V_all / ((rec_all - 0.005)/100) - V_tgt / ((rec_tgt + 0.005)/100), then compute 100 * V / den. The resulting range spans multiple hundredths of a percentage point.

**Suggested fix**  
Either obtain the exact unrounded true link denominators from the underlying linkage datasets, round the reported non-target recall to one decimal place (e.g. 38.6%), or report the uncertainty interval (e.g. [38.57%, 38.60%]).
