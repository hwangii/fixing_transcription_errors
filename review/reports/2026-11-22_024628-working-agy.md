## Findings

### 1. Own-initial ("Share validated, MI") handling of Ancestry-fallback first names differs between target and non-target records and is misstated in tgt_linkage_abe.md

`fallback-mi-asymmetry-and-misstatement` · **MAJOR** · claims-vs-code · confidence: **verified** (traced in source)

**Where:** `MATCHING/score_tgt_links.do:126-131, MATCHING/score_tgt_links.do:322, MATCHING/1e_tgtns_divided_files.do:78-80, MATCHING/1e_tgtns_divided_files.do:121-135`

**What the code does**  
MATCHING/score_tgt_links.do:322 writes into MATCHING/results/tgt_linkage_abe.md: `"As in every column, a 1940 record whose first name fell back to Ancestry's has an empty own initial (1_divide's fallback), so it enters the Ancestry-MI rows but not the own-MI rows."` In MATCHING/1e_tgtns_divided_files.do:78-80,121-135, `mi_ans` is loaded from `divided_file1940_ans_cleaned` and never used; instead, for sentinel first names (`sf == 1`, `f_name == "invalidpred"`), the script runs a second `abeclean` pass on `f_ans` (from which the first `abeclean` pass in `0_create_file_for_matching_intgenV4_women_added.do:87` already stripped the middle initial into `mi`) and sets `replace mi_true_cleaned = mi_rc if sf`, leaving `mi_true_cleaned` empty. However, the claim in score_tgt_links.do:322 is false for non-target records (`target == 0`) in Target-only (`mltgt`) and Target-only, no sentinel (`mltgtns`) (as well as Old): `1c_tgt_divided_files.do:113` executed `replace mi_true_cleaned = mi_ans if !tgt`, which restored `mi_ans` on all non-target records whose first name fell back to Ancestry in `1_divide` (286,969 non-target men in `linkage_sample1940.dta`, visible in `score_tgt_links.log:338-347` where `mi_v_mltgt` has 35,341,502 empty values vs. 35,628,471 in `mi_v_true`). Meanwhile, on target records (`target == 1`) whose first name falls back to Ancestry (whether from empty `namefrst_ml` in `1_divide` or from `"InvalidPred"` in `1e_tgtns_divided_files.do`), `mi_true_cleaned` is left empty (`""`) rather than taking `mi_ans`.

**Why it matters**  
First, the prose in tgt_linkage_abe.md misstates what the table's `"Share validated, MI (%)"` (`sv`) and `"Links with both initials"` (`nv`) rows compute: on non-target records, records without a model first name that fell back to Ancestry are excluded from `sv`/`nv` in New (paper) and New (rerun) (`nv = 2,046,592`, `sv = 88.21%`) but included via `mi_ans` in Target-only and Target-only, no sentinel (`nv = 2,180,928`, `sv = 89.19%`). Second, on target records, every link recovered in Target-only, no sentinel by replacing a sentinel first name (`f_name == "invalidpred"`) with Ancestry's first name is excluded from the headline own-MI validation rows (`sv`, `nv`) even when Ancestry has a middle initial (`mi_ans != ""`) for that person, whereas links recovered by replacing a sentinel surname (`l_name == "invalidpred"`) retain their model first-name initial and enter `sv`/`nv`. Third, `score_tgt_links.do:322` hardcodes `"middle initials as the pipeline's fallback gives them, which leaves them unchanged"`, while lines 128-131 only assert `mi_tgtns == mi_tgt` when `mi_tgt != ""`; if any sentinel row's second `abeclean` pass extracts a non-empty `mi_rc` (`nmi > 0`, as occurred on several of the 436 non-idempotent fallback rows in `_run_tgt_fallback_diag.log:311,513`), the prose in `tgt_linkage_abe.md` will contradict the data without triggering the assertion.

**How to check**  
In Stata after loading linkage_sample1940.dta and merging mi_tgt and mi_tgtns (MATCHING/score_tgt_links.do:109-118), run `count if target==0 & mi_ml=="" & mi_tgt!=""` (which equals 286,969 non-target records where the model had no first name and fell back to Ancestry, per score_tgt_links.log:338-347). In MATCHING/1e_tgtns_divided_files.do, add `quietly count if sf & mi_ans!=""` to count how many sentinel-first-name target records have a non-empty Ancestry middle initial in _ans_cleaned that is discarded by `replace mi_true_cleaned = mi_rc if sf`.

**Suggested fix**  
1. In MATCHING/score_tgt_links.do:322, revise the note so it accurately distinguishes target from non-target records: on target records (and in New (paper) / New (rerun) on all records), a 1940 record whose first name fell back to Ancestry's has an empty own initial due to 1_divide's second abeclean pass on an already-cleaned first name, whereas on non-target records Target-only and Target-only, no sentinel use Ancestry's initial (mi_anc) for every record (including the 286,969 non-target records in the sample where 1_divide fell back to Ancestry's first name). 2. In MATCHING/score_tgt_links.do:128-131, either assert `r(N)==0` on `count if mi_tgtns!=mi_tgt` or interpolate that count into the line-322 note instead of hardcoding `"which leaves them unchanged"`.

### 2. Fallback-consistency gate in 1e_tgtns_divided_files.do shrinks nchk denominator by 71% relative to 1c and can abort after writing the output folder

`tgtns-fallback-gate-shrunk-denominator` · **minor** · correctness · confidence: **verified** (traced in source)

**Where:** `MATCHING/1e_tgtns_divided_files.do:94-100, MATCHING/1e_tgtns_divided_files.do:149-155`

**What the code does**  
Lines 149-155 comment `/*SAME TEST, DENOMINATOR AND TOLERANCE AS 1c (THE 436 KNOWN CASES, tgt_fallback_diag.do)...*/` and run `if `nbad' > 0.001*`nchk' exit 459`. However, in `1c_tgt_divided_files.do:106-109`, `nchk` counted `name_true_cleaned_exists==0` over all records (target and non-target), yielding `nchk = 1,031,654`, `nbad = 436`, and a `0.001 * nchk` threshold of `1,031.65` (`_tgt_only_run.log:3898`). In `1e_tgtns_divided_files.do:96-99`, because `1c` already overwrote non-target records and set `name_true_cleaned_exists = 0 if !tgt`, the check is restricted to `if tgt & name_true_cleaned_exists==0`. Per `_tgt_only_run.log:3893`, there are `17,275,123` target records of which `16,973,070` have `name_true_cleaned_exists==1`, so `nchk` in `1e` is only `302,053` (29.3% of `1c`'s denominator), lowering the `0.001 * nchk` abort threshold from `1,031.65` to `302.05`.

**Why it matters**  
The 436 records where `abeclean` is not idempotent on a second pass are unusual or multi-token Ancestry names, which are disproportionately likely to be target records (`tgt == 1`, where Ancestry and FamilySearch disagree). If 303 or more of the 436 records are in `tgt == 1`, `1e_tgtns_divided_files.do` will exit with code 459 at line 154 after having already written all 139 files in `divided_file1940_tgtns_cleaned`, halting `_tgtns_run.do` before matching and requiring manual removal of the output directory due to the existence guard at lines 46-50.

**How to check**  
Check the log output of `MATCHING/1e_tgtns_divided_files.do:146` (`CHECK: <nbad> of <nchk> records without model names differ from _ans_cleaned`), or in `MATCHING/tgt_fallback_diag.do` merge `tgt_flag1940.dta` onto the `bad` tempfile (436 rows) and run `count if tgt==1` to see whether `nbad` on target records exceeds `0.001 * 302053 = 302.053`.

**Suggested fix**  
Update the comment at MATCHING/1e_tgtns_divided_files.do:149 to reflect that `nchk` in `1e` is restricted to target records without model names (`302,053` rather than `1c`'s all-records denominator `1,031,654`), and gate on the known upper bound (`if `nbad' > 436 exit 459`, since `tgt & name_true_cleaned_exists==0` is a subset of the 436 known cases in `_true_cleaned`) so the tightened denominator cannot cause a spurious `exit 459` after `divided_file1940_tgtns_cleaned` has already been written.

### 3. tgt_linkage_abe.md removes the "InvalidPred" sentinel only in Target-only (mltgtns), leaving New (paper) and New (rerun) contaminated by the sentinel on both target and non-target records

`sentinel-fix-omitted-from-all-records-new-baseline` · **minor** · identification · confidence: **verified** (traced in source)

**Where:** `MATCHING/score_tgt_links.do:9-15, MATCHING/score_tgt_links.do:43-48, MATCHING/score_tgt_links.do:322`

**What the code does**  
`MATCHING/_tgtns_run.do` and `MATCHING/score_tgt_links.do` add `Target-only, no sentinel` (`mltgtns`) to `MATCHING/results/tgt_linkage_abe.md`, while leaving `New (paper)` (`true`) and `New (rerun)` (`ml`) with the literal `"invalidpred"` sentinel in `f_name` and `l_name` on all records (as noted in `score_tgt_links.do:322`: `"New (paper) and New (rerun) still carry the sentinel on every record"`).

**Why it matters**  
Per `MATCHING/results/ditto_diag.md` Section 4, `"InvalidPred"` occurs in 336,679 first names and 271,055 ditto-resolved surnames across the 49 states, of which 298,969 records are in `Target` and the remaining ~250k+ affected records are outside `Target` (where `New` overwrites an agreed human name with `"invalidpred"`, preventing any exact match to 1930 Ancestry names). Consequently, directly comparing `Target-only, no sentinel` against `New (paper)` or `New (rerun)` confounds (a) the methodological choice to replace names only on target records with (b) fixing the pipeline bug that passed `"InvalidPred"` into `abeclean` as a literal name, and part of `New`'s linkage drop on non-target records (`9,756,588` vs. `10,363,116` in `Old`) is an artifact of `"invalidpred"` overwriting agreed non-target names.

**How to check**  
Across the 139 files in `divided_file1940_true_cleaned` merged with `tgt_flag1940.dta` (or `linkage_sample1940.dta`), run `count if !tgt & (f_name=="invalidpred" | l_name=="invalidpred")` to quantify how many non-target men in the 1940 ABE linking pool had their agreed Ancestry/FamilySearch name replaced by `"invalidpred"` in the `New (paper)` and `New (rerun)` columns.

**Suggested fix**  
Either report the count of non-target records in `divided_file1940_true_cleaned` carrying `"invalidpred"` (or add a sentinel-free all-records column `_truens_cleaned` if computationally feasible) or state explicitly in `score_tgt_links.do:322` that comparing `Target-only` vs. `New (rerun)` isolates the target-only restriction (both with sentinel), whereas comparing `Target-only, no sentinel` vs. `Target-only` isolates the sentinel fix on target records.
