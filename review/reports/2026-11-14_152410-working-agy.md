## Findings

### 1. Unrecognized or non-lowercase mode argument silently tests the Ancestry baseline instead of failing

`invalid-placebo-mode-silently-selects-baseline` · **minor** · correctness · confidence: **verified** (traced in source)

**Where:** `MATCHING/check_placebo.do:22-28`

**What the code does**  
The script sets the default filenames to the Ancestry baseline at lines 23-24 (`link1930_1940_ans_cleaned_noraceblock0.dta` and `link1930_1940_fsplacebo1930_1940_cleaned_noraceblock0.dta`), and only switches them to the ML files at lines 25-27 under `if \"`mode'\"==\"ml\"`. Any non-empty argument other than exact lower-case `ml`—such as `ML`, `m1`, or `placebo_ml`—silently leaves the filenames pointing to the Ancestry baseline.

**Why it matters**  
A user who attempts to test the FamilySearch-1930 plus ML-1940 placebo path with an invalid or capitalized mode argument (e.g. `do MATCHING/check_placebo.do ML`) will see the script report `PLACEBO PASSED: identical to link1930_1940_ans_cleaned_noraceblock0.dta`. This provides false assurance that the ML placebo test passed when it was never actually executed.

**How to check**  
Run `do MATCHING/check_placebo.do ML` in Stata and observe that the script proceeds to test `link1930_1940_ans_cleaned_noraceblock0.dta` rather than aborting with an invalid argument error.

**Suggested fix**  
Normalize case and explicitly validate the `mode` parameter before setting filenames: `local mode = lower(strtrim(\"`1'\"))` followed by `if !inlist(\"`mode'\", \"\", \"ml\") { display as error \"check_placebo: invalid mode '`1''. Expected empty or 'ml'.\" \n exit 198 }`.
