### 1. SkipRebuild bypasses Table 4 generation and leaves results/create_figures_SSHA2025.tex empty with 14 pending claims

`skip-rebuild-omits-table4-and-leaves-claims-pending` · **MAJOR** · replication · confidence: **verified** (traced in source)

**Where:** `replication/run_machineA.do:78-79, replication/Run-MachineA.ps1:16-18, replication/results/create_figures_SSHA2025.tex:1-4`

**What the code does**  
In replication/run_machineA.do:78-79, setting REP_SKIP_REBUILD=1 excludes create_figures_SSHA2025 from local scripts. Although documentation states that Table 4 numbers are preserved from the last full run, replication/results/create_figures_SSHA2025.tex contains only header comments and no \newcommand macros. As a result, running Run-MachineA.ps1 -SkipRebuild never verifies or regenerates Table 4 (avg_performance_allstates.tex) or Figures 3-4, and check_claims.py leaves 14 claims permanently in PENDING status.

**Why it matters**  
An external or local replicator running the fast replication tier cannot reproduce or check Table 4 or the 14 dependent in-text claims, because intermediate data rebuilding (lines 48-96) is coupled with exhibit and macro production (lines 107-400) in a single script that is skipped in its entirety.

**How to check**  
Run python replication/check_claims.py to observe 14 claims marked PENDING. Inspect replication/results/create_figures_SSHA2025.tex to verify it contains zero \newcommand macro entries.

**Suggested fix**  
Decouple CODE/create_figures_SSHA2025.do into an intermediate build script and an exhibit/macro generation script that reads temp.dta, or place an if $REP_SKIP_REBUILD == 0 block around lines 48-96 inside create_figures_SSHA2025.do so Table 4, Figures 3-4, and the 14 repnum macros are generated from the existing temp.dta during -SkipRebuild runs.

### 2. Hardcoded absolute bootstrap paths to config.do prevent replication on any clone path or external host

`hardcoded-bootstrap-paths-defeat-centralized-config` · **MAJOR** · replication · confidence: **verified** (traced in source)

**Where:** `replication/run_machineA.do:22, CODE/compute_legibility_quartiles.do:16, CODE/compute_model_agreement_on_discordant.do:47, CODE/compute_race_linkage_rates.do:13, CODE/compute_subgroup_linkage_rates.do:15, CODE/create_figures_SSHA2025.do:24, CODE/make_balance_exhibits.do:30, CODE/verify_inmates_and_county_stats.do:13, replication/config.do:26-29`

**What the code does**  
While replication/config.do was introduced as the single location for machine-specific paths, replication/run_machineA.do:22 and all seven analysis scripts load it via hardcoded absolute path do "D:/repos/fixing_transcription_errors/replication/config.do". Furthermore, config.do:26-29 immediately exits with code 198 if c(hostname) is not ARTS-ECON-CM, and Run-MachineA.ps1:27 hardcodes paper repo path D:\repos\6638fa0fd89fbec05130caeb.

**Why it matters**  
Any replicator cloning the repository to a different directory, drive, or machine cannot run either the master runner or individual scripts standalone, as Stata fails trying to open config.do at the hardcoded D:/repos/... location before any configuration can take effect.

**How to check**  
Clone the repository to an alternate path or run from another drive and execute Stata /b do replication/run_machineA.do; Stata immediately halts with error r(601) attempting to open D:/repos/fixing_transcription_errors/replication/config.do.

**Suggested fix**  
Pass the repository root path via global macro or command-line argument from the PowerShell runners, use relative paths where appropriate, and allow config.do to accept user-defined path overrides or environment variables instead of hardcoding hostnames and drives.

### 3. Age restriction age>=10 retains observations with missing age due to Stata missing value ordering

`age-cutoff-retains-missing-age` · **MAJOR** · correctness · confidence: **likely** (implied, depends on unseen data)

**Where:** `CODE/make_balance_exhibits.do:47, CODE/create_figures_SSHA2025.do:92, replication/claims.toml:398`

**What the code does**  
The sample construction uses keep if age>=10 & female==0 in make_balance_exhibits.do:47 and keep if sex==1 & age>=10 in create_figures_SSHA2025.do:92. In Stata, numeric missing values exceed all finite numbers (. >= 10 is true), so observations with missing age are retained in the sample and incorporated into nMalesTen (55,350,482) and nAnalysis (51,066,203) registered in claims.toml.

**Why it matters**  
If any census records have missing age, the headline population count (55,350,482), analysis sample size (51,066,203), and Table 2-3 balance statistics erroneously include individuals with unknown age. While acknowledged as a known hazard in README.md:214 and claims.toml:398, the uncorrected sample counts continue to be codified as verified targets.

**How to check**  
On the 1940 census extract or intermediate temp.dta, run count if missing(age) & female==0 and count if missing(age) & sex==1 to verify the number of observations retained solely because of missing age.

**Suggested fix**  
Change the filters to keep if age>=10 & !missing(age) & female==0 and keep if sex==1 & age>=10 & !missing(age), report the number of missing-age records dropped, and recompute the registered counts.
