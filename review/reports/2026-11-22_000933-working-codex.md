## Findings

### 1. The reported “linkage erosion” is only raw-string disagreement, not a change in the names used for linkage

`raw-name-disagreement-labeled-linkage-erosion` · **MAJOR** · claims-vs-code · confidence: **verified** (traced in source)

**Where:** `MATCHING/ditto_diag.do:186-216, MATCHING/ditto_diag.do:368-397, MATCHING/1_divide_and_clean_everyoneV5_women_addedV2.do:112-123, MATCHING/1_divide_and_clean_everyoneV5_women_addedV2.do:154-177, LINKAGE/code/01_abe_jw/reference/abeclean.ado:153-240`

**What the code does**  
The diagnostic defines `nt_diff = nt & ((namefrst_u!="" & namefrst_u!=namefrst) | (namelast_u!="" & namelast_u!=namelast))` and labels its rate `Linked name changes on either field (the erosion)`. This compares raw strings in `merged_data.dta`. The production linkage first excludes prediction rows with missing `parsing_quality`, applies field-level Ancestry fallback, and runs `abeclean`, which removes accents and punctuation, extracts first and middle names, removes titles, and applies nickname mappings. Thus raw differences can collapse to identical linkage names, while other transformations can change initials or cleaned values.

**Why it matters**  
The Wyoming smoke report’s 8.27% is not the share whose linkage inputs changed and is not the share of links lost. Treating it as the erosion caused by replacing non-target names can materially misdiagnose why the all-record policy performs worse; actual link outcomes also depend on cleaning, candidate uniqueness, and changes to competing records.

**How to check**  
On the non-target sample, construct the production model-plus-fallback and Ancestry names, enforce `parsing_quality!=.`, run both through `abeclean` with the production options, and tabulate `raw_change` against `cleaned_change`. Then merge the old and all-record link outputs by record ID and count actual gained, lost, and changed links.

**Suggested fix**  
Either relabel `nt_diff` as raw transcription disagreement or reproduce the production cleaning and eligibility logic before calling it a linked-name change. To explain erosion in link rates, report actual before/after link transitions rather than inferring them from name inequality.

### 2. A selected FamilySearch-linked reference is incorrectly designated as the truth check

`familysearch-profile-called-truth-check` · **MAJOR** · claims-vs-code · confidence: **verified** (traced in source)

**Where:** `MATCHING/ditto_diag.do:47-48, MATCHING/profile_names_build.do:3-7, MATCHING/profile_names_build.do:83-90, MATCHING/profile_names_jw.do:197`

**What the code does**  
The new script states that `THE TRUTH CHECK IS THE FAMILYSEARCH-PROFILE COMPARISON`. The referenced profile code instead measures agreement or Jaro-Winkler similarity among records attached one-to-one to FamilySearch profiles and explicitly describes the result as `Agreement with a selected, FamilySearch-linked reference, not accuracy`.

**Why it matters**  
The profile comparison cannot establish which transcription is correct and may favor FamilySearch-like readings because the reference sample is reached through FamilySearch linkage. Calling it truth would leave any resulting accuracy or correctness claim unsupported.

**How to check**  
Run `rg -n "TRUTH CHECK|AGREEMENT, NOT ACCURACY|FamilySearch-linked reference" MATCHING/ditto_diag.do MATCHING/profile_names_build.do MATCHING/profile_names_jw.do` and trace the profile attachment restrictions. An actual truth check requires an independently hand-transcribed image sample.

**Suggested fix**  
Replace “truth check” with “external profile-agreement comparison” and preserve the selection caveat. Use an independent, documented hand-validation sample for accuracy or correctness claims.

**Why it matters**  
If these untracked files are committed, the repository will contain a result with false provenance and a temporary launcher that is not portable. A replicator cannot generate the smoke artifact by running the checked-in diagnostic unchanged.

**How to check**  
Run `git status --short`, compare the state table in `MATCHING/results/ditto_diag_SMOKE.md` with the assertions in `MATCHING/ditto_diag.do`, and run `rg -n "49 model states|\| wy \|" MATCHING/results/ditto_diag_SMOKE.md`.

**Suggested fix**  
Remove both scratch artifacts before committing, or add a parameterized smoke harness whose state list, assertions, output path, and generated header all derive from the same configuration. Ignore `_run_*.do` runner files.
