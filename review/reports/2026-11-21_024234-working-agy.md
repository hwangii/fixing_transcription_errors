### 2. `img_fail` includes each record in its own image-level failure mean after dropping concordant records, creating a mechanical disparity in `"Image mostly failing (%)"` across columns

`nomodel-diag-own-observation-image-clustering-bias` · **MAJOR** · identification · confidence: **verified** (traced in source)

**Where:** `MATCHING/nomodel_diag.do:30,34-36,104-110`

**What the code does**  
Line 30 filters to discordant human-complete records (`keep if namefrst!="" & namelast!="" & fs_namefrst!="" & fs_namelast!="" & !(namefrst==fs_namefrst & namelast==fs_namelast)`), and lines 34-36 then compute `gen byte fail = ftype>0`, `bysort filename: egen double img_fail = mean(fail)`, and `bysort filename: gen long img_n = _N`. Lines 104-110 tabulate `"Image mostly failing (%)"` (`img_fail > 0.5`) across `ftype == 0` (`fail == 0`, "Both names") and `ftype == 1, 2, 3` (`fail == 1`, the three no-output categories).

**Why it matters**  
Because `img_fail` is computed after dropping ~73% of lines (concordant records) and includes record $i$'s own `fail` indicator in `(fail_i + sum_{j!=i} fail_j)/img_n`, comparing `img_fail > 0.5` across groups defined by `fail_i == 0` (`ftype == 0`) vs. `fail_i == 1` (`ftype > 0`) has a severe mechanical bias whenever `img_n` is small. On any image with `img_n == 1` target record, `img_fail > 0.5` is identically 0% for `ftype == 0` and identically 100% for `ftype in {1,2,3}` even when zero other records on the image failed. On any image with `img_n == 2` target records, `img_fail` for `ftype == 0` is at most `1/2 = 0.5` (so `img_fail > 0.5` is still mechanically 0%), whereas for `ftype in {1,2,3}` it exceeds `0.5` whenever the single other target record fails. This overstates image-level clustering of model failures relative to `Both names`.

**How to check**  
After loading a state in `MATCHING/nomodel_diag.do`, run `tab img_n if img_n<=5` and compare `count if ftype==t & img_fail>0.5` against the leave-one-out rate `count if ftype==t & (img_fail*img_n - fail)/(img_n - 1) > 0.5 & img_n > 1`, as well as against image failure computed before line 30's `keep if`.

**Suggested fix**  
Compute full-image size and failure rate before line 30's `keep if` (over all rows on `filename`), and for target-record image clustering compute the leave-one-out failure share among *other* records on the image (`(sum_fail - fail)/(img_n - 1)` for `img_n > 1`, reporting `img_n == 1` separately) so a record's own failure status does not mechanically drive `"Image mostly failing (%)"`.

### 3. `bysort filename:` does not exclude empty `filename == ""`, which would pool all unmatched records in a state into one synthetic image

`nomodel-diag-empty-filename-grouping-and-duplicates` · **MAJOR** · correctness · confidence: **likely** (implied, depends on unseen data)

**Where:** `MATCHING/nomodel_diag.do:29,35-36,106,114`

**What the code does**  
Lines 35-36 run `bysort filename: egen double img_fail = mean(fail)` and `bysort filename: gen long img_n = _N` without asserting `filename != ""` or restricting to non-empty `filename`.

**Why it matters**  
In Stata, `bysort filename:` groups all rows with `filename == ""` in a state into a single group. If any target records in `merged_data.dta` have `filename == ""` (e.g., human census records that did not link to an ML image record when `merged_data.dta` was built, all of which have `ftype == 1`, "Both empty"), every such record in the state gets assigned `img_fail = 1.0` (`> 0.5`) and `img_n` equal to the state's total unmatched target record count $M$. In the record-weighted mean at line 114 (`quietly sum img_n if ftype==1`), those $M$ records contribute $M^2$ to the sum, distorting both `"Mean target records per image"` and `"Image mostly failing (%)"`. Furthermore, `MATCHING/profile_names_build.log:733-740` shows `merged_data.dta` has 128,837 duplicate human-complete rows sharing a `histid`, which also inflate `img_n` on affected images.

**How to check**  
Run `count if filename==""` and `bysort st filename linep: count if _N>1` across the appended dataset in `MATCHING/nomodel_diag.do`.

**Suggested fix**  
Check for empty `filename` (`count if filename==""`) inside the state loop and compute `bysort filename: egen double img_fail = mean(fail) if filename!=""` and `bysort filename: gen long img_n = _N if filename!=""`, reporting records with `filename==""` separately rather than pooling them into one image group.

### 4. Unquoted `` `v'==`val' `` in `levelsof` loop will crash if `non_ditto_ml` is stored as a string variable

`nomodel-diag-unquoted-levelsof-comparison` · **minor** · correctness · confidence: **likely** (implied, depends on unseen data)

**Where:** `MATCHING/nomodel_diag.do:120-139`

**What the code does**  
Lines 120-139 iterate `foreach v in non_ditto non_ditto_ml`, extract distinct values via `quietly levelsof `v', missing local(vals)`, and count matches at line 134 with `quietly count if ftype==`t' & `v'==`val'`.

**Why it matters**  
`non_ditto` is constructed as numeric (`1` or `.`) in `CODE/clean_FS_and_combineV5_nber.do:100`, whereas `non_ditto_ml` comes from the external ML pipeline (`merged_data.dta`). If `non_ditto_ml` is stored as a string variable, `foreach val of local vals` strips quotes from `levelsof` tokens: an empty-string level `""` expands line 134 to `quietly count if ftype==0 & non_ditto_ml==` (`r(198)` syntax error) and non-empty string levels expand to unquoted tokens (`r(109)` type mismatch or `r(111)` not found), aborting the script after all 49 states have been loaded and leaving `MATCHING/results/nomodel_diag.md` partially written.

**How to check**  
Run `describe non_ditto non_ditto_ml using "$REP_SNU/fixing_transcription_errors/DATA/TRANSCRIPTIONS/USCensus1940FullCount/output_and_output1_ssha2025/de/merged_data.dta"` to verify whether both variables are numeric across all states.

**Suggested fix**  
Before the `foreach val of local vals` loop at line 129, check `capture confirm string variable `v'` and use ``quietly count if ftype==`t' & `v'==`"`val'"'`` when `_rc == 0` and ``quietly count if ftype==`t' & `v'==`val'`` when numeric.
