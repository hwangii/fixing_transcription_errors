## Findings

### 1. The target-only files exclude records that the paper classifies as targets

`target-only-rule-does-not-match-paper-target` · **MAJOR** · correctness · confidence: **verified** (traced in source)

**Where:** `MATCHING/1c_tgt_divided_files.do:53, MATCHING/1c_tgt_divided_files.do:60-64, MATCHING/fs_avg_performance.do:79-83, MATCHING/fs_cells.do:73-82`

**What the code does**  
The new flag is `namefrst!="" & namelast!="" & fs_namefrst!="" & fs_namelast!="" & !(namefrst==fs_namefrst & namelast==fs_namelast)`, and any histid with conflicting duplicate flags is forced to zero. The established paper target is simply `!(namefrst==namefrst_fs & namelast==namelast_fs)`; `fs_cells.do` explicitly reserves cell 5 for target records with an empty human field.

**Why it matters**  
Discordant records with one or more blank human fields—and conflicting duplicate histids—retain Ancestry names in the purported target-only treatment. Consequently, linkage rates from this output do not answer what happens when model names are substituted only for the paper's target set. The affected count cannot be established without the data, but the definitions demonstrably differ.

**How to check**  
In Stata, construct both flags on the canonical 1940 labeled data and run `tab paper_target new_tgt, missing`; then merge `tgt_flag1940.dta` by histid and run `count if paper_target==1 & tgt!=1`. Also report the number of cell-5 records from `MATCHING/fs_cells.do`.

**Suggested fix**  
Build the flag from the same canonical dataset and exact expression used by `fs_avg_performance.do`, or explicitly redefine and relabel the estimand. Do not silently set conflicting duplicate flags to zero; assert uniqueness or reconcile them against the canonical record, and add an assertion that the resulting target count and membership match the analysis sample.

### 2. The no-overwrite driver silently replaces existing divided and match files

`overwrite-guard-misses-intermediate-products` · **MAJOR** · replication · confidence: **verified** (traced in source)

**Where:** `MATCHING/_tgt_only_run.do:21-36, MATCHING/1c_tgt_divided_files.do:133, MATCHING/2_ABE_matchingV3_christian_torben.do:158-169`

**What the code does**  
The driver checks only whether the two final `link1930_1940_{mltgt1940,ml1940}_cleaned_noraceblock0.dta` files exist. It then writes every target divided file with `save ..., replace` and invokes `abematch ... save($outputfile) replace`, including the `_ans_cleaned` to `_true_cleaned` intermediate directory already used by the paper's ML links.

**Why it matters**  
Running the advertised driver can overwrite existing paper-era intermediate matches and an existing target divided-file folder. An interrupted run can leave a mixture of old and new birthplace outputs, undermining reproducibility and contradicting the script's statement that neither existing link files nor divided-file folders are overwritten.

**How to check**  
Before running, list timestamps or hashes under `divided_file1940_tgt_cleaned`, `r_ans_cleaned_tgt_cleaned1930_1940`, and `r_ans_cleaned_true_cleaned1930_1940`; the current preflight checks none of these paths. A dry inspection of `_tgt_only_run.do` confirms that only the two final files are tested.

**Suggested fix**  
Write this run to fresh, versioned divided and match directories, or refuse to start if any destination directory/file already exists. If intentional rebuilding is required, validate that the directory is complete and isolated before replacing it, and revise the no-overwrite claim.
