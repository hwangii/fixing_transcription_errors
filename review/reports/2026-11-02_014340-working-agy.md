## Findings

### 1. Reintroducing a moving 1940 middle-initial validator invalidates the headline 28% match-quality improvement claim

`moving-validator-inflates-match-quality` · **BLOCKER** · claims-vs-code · confidence: **verified** (traced in source)

**Where:** `CODE/create_figures_SSHA2025.do:70-86, D:/repos/6638fa0fd89fbec05130caeb/DHTS-2026-10-12.tex:68, D:/repos/6638fa0fd89fbec05130caeb/DHTS-2026-10-12.tex:98, D:/repos/6638fa0fd89fbec05130caeb/DHTS-2026-10-12.tex:547-549, replication/results/validation_fixed_initials.tex:28-30, replication/results/validation_fixed_initials.tex:68-70`

**What the code does**  
CODE/create_figures_SSHA2025.do:70-86 reverts the 2026-11-01 fix, redefining `validated_before = mi`beg_yr'==mi1940` using mi1940 from the Ancestry link file, and `validated_after = mi`beg_yr'==mi1940` using mi1940 from the ML model link file. The expression `100*((sv_after/sv_before)-1)` in line 211 computes the percentage change when both the link partner and the 1940 evaluation standard change simultaneously.

**Why it matters**  
The paper's Abstract (line 68), Introduction (line 98), and main results (lines 547-549) claim a 28% increase in match quality (65% to 84%) on discordant records, arguing that recovered links are true rather than spurious. When the validator is held fixed, the true link-quality gain is only 16.0% (Ancestry initial) or 11.5% (FamilySearch initial). For 829,471 kept target links pairing the exact same individuals, validation jumps from 63.4% to 79.2% solely because the 1940 initial was re-transcribed. Reverting to the moving validator produces an inflated number that fails like-for-like comparison.

**How to check**  
Run `replication/diagnostics/validation_fixed_initials.do` and compare `valGainTarget` (28%) with `valGainAncTarget` (16.0%) and `valGainFsTarget` (11.5%). In Stata on `temp.dta`, tabulate `validated_before validated_after if linked_before==1 & linked_after==1 & id_A_before==id_A_after`: 165,580 kept records change validation status solely because mi1940 changed.

**Suggested fix**  
Do not revert create_figures_SSHA2025.do to own-file middle initials. Retain one fixed 1940 middle initial (Ancestry or FamilySearch) across both before and after link files, and update the paper text (lines 68, 98, 548) and Table 4 to report the true fixed-validator gain (16.0% under Ancestry, 11.5% under FamilySearch). If the 28% moving figure is retained in an appendix, explicitly describe it as conflating link changes with middle-initial transcription changes rather than 'match quality'.

### 2. Counterfactual in new validation decomposition misclassifies validator shifts on switched links as linkage effects

`switched-links-contaminate-decomposition` · **MAJOR** · correctness · confidence: **verified** (traced in source)

**Where:** `replication/diagnostics/validation_by_link_status.do:93-109, replication/diagnostics/validation_by_link_status.do:27-33`

**What the code does**  
Lines 93-94 define `gen byte v_cf = validated_after if linked_after==1` and `replace v_cf = validated_before if status==1`. For switched links (`status==2`), `v_cf` retains `validated_after` (which uses the new model's 1940 initial). The code then defines `ppLinks = 100*(cf - b)` as the effect of 'which links exist' and `ppRescoring = 100*(a - cf)` as the effect of rescoring. For all switched links, `a - cf` is identically 0.

**Why it matters**  
The new decomposition claims to separate linkage composition from validator rescoring. Because `v_cf` is not adjusted for switched links (16,435 records in the target group where validation moves from 33.6% to 75.1%), all rescoring of switched links is attributed to the link-existence component `ppLinks`. Furthermore, because `summarize` omits missing initials and initial availability shifts between versions (21,925 gained vs 71,780 lost on kept records), the decomposition operates over shifting denominators.

**How to check**  
In Stata, inspect `v_cf` on switched links: `count if status==2 & v_cf != validated_after` returns 0. Compare `v_cf` with a true fixed-initial counterfactual `mi1930_after == mi1940_anc` for `status==2`: the two differ, proving that `ppLinks` absorbs the validator shift on switched links.

**Suggested fix**  
Construct the counterfactual validation flag using a constant 1940 middle initial (e.g. Ancestry's `mi1940_anc`) across all link categories: for after links, evaluate `mi1930_new == mi1940_fixed` for both kept (status==1) and switched (status==2) links. Decompose relative to that fixed baseline, and account for denominator attrition from missing initials.
