### 1. The output omits that its 1940 men are selected on matched, complete Ancestry and FamilySearch records

`selected-transcription-sample-not-disclosed` · **MAJOR** · identification · confidence: **verified** (traced in source)

**Where:** `MATCHING/linked_groups_socio.do:3-5, MATCHING/linked_groups_socio.do:110, review/briefs/2026-11-19-linked-groups-socio.md:3-5, CODE/clean_FS_and_combineV5_nber.do:193, CODE/clean_FS_and_combineV5_nber.do:225, CODE/create_figures_SSHA2025.do:69, CODE/create_figures_SSHA2025.do:87, CODE/create_figures_SSHA2025.do:115`

**What the code does**

Its source dataset was first restricted by `keep if _merge==3`, then by `keep if namelast!="" & namefrst!="" & namefrst_fs!="" & namelast_fs!="" & age!=. & age_fs!=.`, and later by the IPUMS merge and sex/age restriction. It therefore profiles the comparison-transcription analysis sample, not all 1940 men aged 10+.

**Why it matters**  
The full census extract contains 55,347,491 men aged 10+, versus 51,036,859 here—a selected exclusion of 4,310,632 records. Availability of matched, nonempty transcriptions can correlate with race, nativity, legibility, and linkability, so the profiles cannot be generalized to all men without disclosing and assessing that selection.

**Suggested fix**  
Describe the population everywhere as “1940 men aged 10+ in the analysis sample, with all four human name fields present” and state the 55,347,491-to-51,036,859 selection. If the intended claim concerns all men, rebuild the profile from the full extract and report missing-source records separately.

### 2. The “after” description says target records use model names even when the pipeline falls back to Ancestry

`target-policy-omits-ancestry-fallback` · **minor** · claims-vs-code · confidence: **verified** (traced in source)

**Where:** `MATCHING/linked_groups_socio.do:5-6, MATCHING/linked_groups_socio.do:110, MATCHING/1c_tgt_divided_files.do:7-11, MATCHING/1c_tgt_divided_files.do:105-126`

**What the code does**  
The output writes `After = our names on target records, Ancestry's elsewhere`. The target-only builder instead takes target records from `_true_cleaned`, explicitly defined as `model names, Ancestry's where the model gave none`; only targets with `name_true_cleaned_exists==1` actually have model names.

**Why it matters**  
Target status is not equivalent to receiving a model transcription. Model availability can vary with the socio-demographic characteristics being profiled, so describing all target records as model-treated can misattribute link-status differences to the model.

**How to check**  
Run `tab tgt name_true_cleaned_exists` while constructing the target-only files, or inspect `MATCHING/_tgt_only_run.log:3891-3894`, where 302,053 of 17,275,123 target records lack model names and retain Ancestry upstream.

**Suggested fix**  
Change the note to “model names on target records where available, with Ancestry fallback; Ancestry on non-target records.” If the table will support claims about beneficiaries, also report model-name availability within each link-status group.

### 3. The nonwage-income labels put the $50 boundary in the wrong category

`nonwage-cutoff-labeled-backwards` · **minor** · correctness · confidence: **verified** (traced in source)

**Where:** `MATCHING/linked_groups_socio.do:64, MATCHING/linked_groups_socio.do:103, CODE/label_socio_demo.do:85, CODE/usa00647_for_SSHA2025_socio_demo_char.do:3764-3768`

**What the code does**  
The script retains `incnonwg` codes 1 and 2, then labels them `Nonwage inc.<=50` and `Nonwage inc.>50`. The source labels define code 1 as `Less than $50` and code 2 as `$50+`, so observations at exactly $50 are printed in a row whose label excludes them.

**Why it matters**  
The shares are computed correctly, but the emitted table misstates the substantive category boundary.

**How to check**  
Run `label list incnonwg_lbl` after loading the source extract, or inspect the label definitions at `CODE/usa00647_for_SSHA2025_socio_demo_char.do:3764-3768`.

**Suggested fix**  
Label code 1 as `Nonwage inc.<$50` and code 2 as `Nonwage inc.$50+` (or `>= $50`).
