### 1. The new denominator artifact is manually transferred and absent from the committed input manifest

`new-sample-outside-replication-pipeline` · **MAJOR** · replication · confidence: **verified** (traced in source)

**Where:** `LINKAGE/code/prep/build_linkage_sample1940.do:16-18, LINKAGE/code/prep/build_linkage_sample1940.do:27, LINKAGE/code/prep/_run_build_linkage_sample1940.do:1-2, LINKAGE/code/shared/verify_paths.do:80-85, replication/run_machineB.do:59-65, replication/hash_inputs_machineB.py:35, replication/input_manifest_machineB.md:4-27`

**What the code does**  
The builder script `build_linkage_sample1940.do` creates `linkage_sample1940.dta` in Machine A's intermediate folder, but is only invoked via an untracked scratch wrapper (`_run_build_linkage_sample1940.do`) and is not integrated into `run_machineA.do`. Its header notes that the output must be copied manually via Dropbox to Machine B's `$D_FLAGS`. On Machine B, `run_machineB.do` and `hash_inputs_machineB.py` were adjusted to 15 inputs (adding `linkage_sample1940.dta` and dropping three superseded 1940 files), but `input_manifest_machineB.md` was not regenerated and still lists 17 inputs, retains the superseded files, and lacks a hash for `linkage_sample1940.dta`. Additionally, `verify_paths.do` added `linkage_sample1940.dta` but still requires the three superseded files.

**Why it matters**  
Running `python replication/hash_inputs_machineB.py --check` on Machine B will immediately fail because `linkage_sample1940.dta` is missing from `input_manifest_machineB.md`. Furthermore, an external replicator running the master pipelines from scratch cannot reproduce Tables 5–8 because Machine A's master script does not build `linkage_sample1940.dta`, and Machine B's run will fail if the multi-gigabyte file is not manually copied between machines.

**How to check**  
Run `python -c "import replication.hash_inputs_machineB as h; print('\n'.join(h.input_list()))"` and compare its 15 returned paths against `replication/input_manifest_machineB.md`; check `replication/run_machineA.do` to confirm that `build_linkage_sample1940.do` is never executed; and run `verify_paths.do` to confirm that it still checks the three superseded files.

**Suggested fix**  
Add `build_linkage_sample1940.do` to the Machine-A master execution pipeline (`run_machineA.do` / `Run-MachineA.ps1`), script the transfer to Machine B's expected path, update `verify_paths.do` to remove checks for the three superseded files, and regenerate `replication/input_manifest_machineB.md` on Machine B so it hashes the 15 active inputs and moves the superseded files to the `## Superseded` section.

### 2. Old vs. New middle-initial match rates switch the validating transcription between columns, conflating link selection with re-transcription

`moving-middle-initial-validator` · **MAJOR** · identification · confidence: **verified** (traced in source)

**Where:** `LINKAGE/code/01_abe_jw/linkage_analysis.do:242-254, LINKAGE/code/01_abe_jw/linkage_analysis.do:510-512, LINKAGE/code/02_hlink/linkage_analysis_newlinks.do:371-386, LINKAGE/code/02_hlink/linkage_analysis_newlinks.do:551-553`

**What the code does**  
For Old links, `miv` is set to Ancestry's initial `mi_anc`, whereas for New links it is set to the ML model's initial `mi_ml`. The code evaluates `count if mi1930 == mi1940` and displays the resulting rates side by side as `MI Match Rate (%)` in Panel A under the heading `Coverage and Link Quality`.

**Why it matters**  
Middle-initial agreement is used in the historical linkage literature as an external validator of match correctness. By switching the 1940 validating initial from Ancestry to ML between columns, the comparison does not isolate link quality from transcription quality. As demonstrated in `replication/diagnostics/validation_fixed_initials.do:78-79`, for every link kept unchanged between Old and New, validation status cannot change under a fixed 1940 initial (`assert vb_`src'==va_`src' if status==1`). Under the moving validator, however, rates change purely because the ML model re-transcribed 324,768 initials differently from Ancestry. Although the revised captions disclose the own-initial convention, placing this in Panel A under 'Link Quality' attributes transcription shifts to linking improvements. A referee will demand a fixed-validator comparison.

**How to check**  
Run `replication/diagnostics/validation_fixed_initials.do`, which proves on the main sample that kept links cannot change validation status under a single fixed 1940 validator and decomposes the share of gains due to re-transcription vs. link selection. In `linkage_analysis.do`, compute the MI match rate using `mi_anc` fixed for both Old and New links to see how much the apparent link quality gain diminishes.

**Suggested fix**  
Report middle-initial validation rates against a single fixed human validator (e.g., `mi_anc` or `mi_fs` across all columns) to isolate true link-quality improvements. If own-transcription validation is retained, label the row explicitly as 'Own-Transcription Initial Agreement (%)' and distinguish it clearly from independent linkage validation.
