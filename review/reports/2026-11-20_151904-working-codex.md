## Findings

### 1. Records outside the labeled target universe are silently assigned to the non-target policy

`unknown-target-status-coded-nontarget` · **MAJOR** · identification · confidence: **likely** (implied, depends on unseen data)

**Where:** `MATCHING/1c_tgt_divided_files.do:52-65, MATCHING/1d_for_mlp_tgt.do:79-87, MATCHING/tgt_fallback_diag.do:4-9`

**What the code does**  
The flag producer retains only `keep if tgt`. The new export then executes `merge 1:1 id using ... keep(1 3)` followed by `replace tgt = 0 if _merge==1`. Thus an observed Ancestry–FamilySearch agreement and an ID absent from `census1940_all_labeled_data.dta` receive the same `tgt=0`, after which lines 84-87 replace the model fields with Ancestry fields. The repository diagnostic documents 4,819,575 absent IDs in the corresponding male divided-file build.

**Why it matters**  
Target status is unobserved for these records, not known to be non-target. Forcing them to use Ancestry names can change their own HLINK candidates and competition faced by labeled records, so a resulting change cannot be interpreted purely as replacing names only where the commercial sources disagree. The exact magnitude in the new men-and-women source remains data-dependent.

**How to check**  
Build a full flag containing every labeled `histid`, `tgt`, and an `in_labeled=1` indicator before `keep if tgt`; merge it into each `_women_added` partition and accumulate `count if _merge==1`, tabulating those records by sex and finite age. Then compare target-only HLINK output under two policies for `_merge==1`: Ancestry names versus model names.

**Suggested fix**  
Preserve known non-targets and unknown-status records as separate categories. Either assert complete labeled coverage for the HLINK candidate universe, retain model names for unknown records and label the policy accordingly, or report a sensitivity run showing that the alternative assignment does not affect the paper sample or its candidate competition.

### 2. The new target-only MLP path ends at a manually submitted input file

`target-mlp-path-not-wired-end-to-end` · **MAJOR** · replication · confidence: **verified** (traced in source)

**Where:** `MATCHING/1d_for_mlp_tgt.do:17-38, MATCHING/1d_for_mlp_tgt.do:105-116, MATCHING/_tgt_only_run.do:46-52, replication/run_machineA.do:96-106, LINKAGE/LINKAGE_README.md:225-239`

**What the code does**  
The new script requires a pre-existing `tgt_flag1940.dta` and writes only `for_mlp1940_tgt.dta`. `_tgt_only_run.do` creates the flag but proceeds through the ABE matcher without calling this script, while the machine-A master does not call either target builder. The subsequent HLINK computation is explicitly third-party and its code is absent, leaving no repository command from frozen inputs through target-only HLINK links.

**Why it matters**  
Any target-only HLINK number generated from this file will depend on an undocumented manual submission and external configuration. A replicator cannot regenerate the proposed result or establish that the baseline and target-only runs used identical HLINK versions, settings, and arbitration rules.

**How to check**  
Run `rg -n "1d_for_mlp_tgt|for_mlp1940_tgt" replication MATCHING LINKAGE`; references stop at the new builder itself. Then follow the HLINK provenance at `LINKAGE/LINKAGE_README.md:225-239`, which begins with third-party raw output rather than a producing command.

**Suggested fix**  
Add a documented driver that builds or verifies the full target flag, runs this export, records input counts and hashes, and identifies the exact external HLINK version, settings, and submission procedure. Archive hashes of the outgoing DTA and returned raw files and wire their cleanup and scoring into the replication sequence; if the service remains a black box, state that limitation explicitly.

### 3. Target records without model output are not guaranteed to receive the promised Ancestry fallback

`no-model-targets-can-keep-nonancestry-fallback` · **minor** · correctness · confidence: **likely** (implied, depends on unseen data)

**Where:** `MATCHING/1d_for_mlp_tgt.do:10-13, MATCHING/1d_for_mlp_tgt.do:84-87, MATCHING/1c_tgt_divided_files.do:105-109, MATCHING/1c_tgt_divided_files.do:128-135`

**What the code does**  
The export overwrites the alternative fields with Ancestry only `if !tgt`. A target with `name_true_cleaned_exists==0` therefore retains the `_true_cleaned` fields. The upstream check already reports 436 no-model records for which `!(f_name==f_ans & l_name==l_ans)`, so any of those that are targets contradict the stated rule that target records use Ancestry where the model supplied no name. Middle initials are not included in that discrepancy check.

**Why it matters**  
Such records can enter HLINK with changed names or initials even though the model produced no transcription. That contaminates the intended model-versus-Ancestry contrast and can affect candidate uniqueness, although the documented discrepancy count is small and its target share is unknown.

**How to check**  
Immediately before lines 84-87, run `count if tgt & name_true_cleaned_exists==0 & (namefrst_true_cleaned!=f_name | namelast_true_cleaned!=l_name | mi_true_cleaned!=mi)` and tabulate `tgt` among all no-model source discrepancies.

**Suggested fix**  
For every record with `name_true_cleaned_exists==0`, copy all three Ancestry fields regardless of `tgt`, then assert exact equality. Reconcile the 436 upstream discrepancies and include `mi_true_cleaned!=mi` in the guard.
